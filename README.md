# Диспетчерская с ИИ — команда «1+∞»

Прототип ИТ-диспетчерской для кейса 9 «Диспетчерская с ИИ» (Газпром трансгаз Сургут),
хакатон UgraCode, номинация Pro.

**Что делает:** обращение сотрудника (текст в чате, звонок, скриншот) превращается в готовую
заявку — поля с цитатами и уверенностью, приоритет по регламенту, топ-3 исполнителя
с объяснением, решение из базы знаний и похожие заявки. **Последнее слово всегда за человеком:**
диспетчер правит сомнительное и подтверждает, каждая правка остаётся в журнале.

- Демо-стенд: **❓ адрес** (запасная копия — на сервере владельца, ❓ адрес)
- Скриншоты интерфейса: **❓** (задача 026)
- Что передаём заказчику и статус каждого пункта: [docs/hackathon/delivery.md](docs/hackathon/delivery.md)
- Честные ограничения версии: [docs/knowledge/limitations.md](docs/knowledge/limitations.md)

## Запуск одной командой

```bash
cp .env.example .env      # пустой POLZA_API_KEY — демо на заглушке, без сети
docker compose up --build
```

| Что | Адрес |
|---|---|
| Веб-интерфейс | http://localhost:5173 |
| API и health-check | http://localhost:3001/api/health |
| PostgreSQL 16 + pgvector | порт 5432 |

С ключом `POLZA_API_KEY` в `.env` работает живая модель (`AI_MODE=cloud`), без ключа —
`AI_MODE=stub`: те же шаги демо на записанных ответах. База наполняется автоматически
(миграция + сид: справочники, CMDB, 14 инженеров, ~600 заявок истории, 10 статей базы знаний).

## Локальная разработка

```bash
pnpm install
cp .env.example .env
pnpm migrate && pnpm seed   # нужен PostgreSQL (docker compose up -d db)
pnpm dev:api                # http://localhost:3001
pnpm dev:web                # http://localhost:5173
```

## Звонок с телефона

При работающем API запустите `pnpm demo:tunnel`. Команда собирает веб и печатает проверенную
временную HTTPS-ссылку `/call` и QR в терминале. Откройте её на телефоне; во вкладке «Звонок»
диспетчер видит разговор и созданную заявку. Для обновления адреса: Ctrl+C и та же команда.
Если Pinggy не открывается на телефоне, используйте другой домен: `pnpm demo:tunnel --serveo`
(на заставке нажать **Continue to Site**).
Подробнее: [голосовой модуль](modules/voice-call/README.md#как-позвонить-с-телефона).

## Проверки

```bash
pnpm check                              # типы + ESLint (границы слоёв) + Vitest
pnpm eval                               # прогон контрольного набора → reports/quality.md
python3 -m unittest discover -s tests   # ссылки документации
```

`pnpm eval --cloud` — тот же набор через Polza (нужен ключ), `pnpm eval --case 04` — один кейс
с трассировкой. Сквозной срез «текст → заявка»: `npx vitest run apps/api/tests/e2e.test.ts`.

## Архитектура

Модульный монолит: один сервер, одно веб-приложение, одна база.

```
apps (api, web) → modules → adapters, db → core → contracts
```

- **Ядро** (`packages/core`) — пайплайн разбора по стадиям, шина событий (она же журнал действий),
  реестры полей/экранов/отчётов, флаги фич, сервис заявок и статусов.
- **Модули** (`modules/<id>`) — фичи: извлечение полей, приоритет, маршрутизация, авария,
  база знаний, проверка диспетчером, отчёты, качество. Новая фича — папка в `modules/`
  и одна строка в манифесте; модули не импортируют друг друга.
- **Агент с инструментами** — модель не «угадывает» поля, а ходит в справочники, CMDB и базу
  знаний через инструменты; каждый шаг и цитата сохраняются в следе разбора.
- **Порты** (`packages/core/src/ports/`) — LLM, речь, изображения, эмбеддинги, CMDB, история,
  уведомления. Облако Polza — текущая реализация; локальные модели подключаются заменой адаптера
  (закрытый контур, в этой версии не разворачивались).

Подробно: [docs/specs/case9-core.md](docs/specs/case9-core.md) и [docs/map/README.md](docs/map/README.md).

## Роли и экраны

| Роль | Что делает | Экраны |
|---|---|---|
| Заявитель | описывает проблему в чате, отвечает на вопросы-карточки, видит статус и подтверждает выполнение | «Обращение», «Мои заявки» |
| Диспетчер | проверяет разбор, правит сомнительные поля, подтверждает и назначает | «Очередь», карточка проверки, «Аварии», «Журнал», «Исполнители» |
| Инженер | берёт задачу, смотрит диагностику и похожие заявки, фиксирует результат | «Мои задачи», «База знаний» |
| Руководитель | смотрит метрики, SLA, качество ИИ и отчёты с выводами | «Дашборд», «Отчёты», «Качество ИИ» |

Вход — выбор готового пользователя по ролям (регистрации нет). Права проверяются на сервере.
