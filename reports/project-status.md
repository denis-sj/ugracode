# Статус проекта: что сделано

Дата: 2026-11-14
Ветка: `feature/ui-redesign` (HEAD `a7374da`)
Стек: TypeScript, Node.js 22, Fastify, PostgreSQL 16 + pgvector, React + Vite, Docker Compose.

## 1. Итог в одном абзаце

Собран рабочий продукт кейса 9: чат заявителя с живым разбором ИИ, заявки с цитатами и уверенностью,
очередь и проверка диспетчером, аварии и массовость, рабочее место инженера, база знаний, качество ИИ,
замер «с ИИ / без ИИ», отчёты О1–О7, профиль и тёмная тема. Ядро модульное: новая фича — папка в
`modules/` и одна строка в реестре. Демо-сценарий проходит смоук **10/10** на живом стеке.

## 2. Что готово по блокам

### Ядро и контракты
- Zod-контракты домена, полей, событий, ответа модели и API; типы из одной схемы.
- Пайплайн: стадии, `order`, параллельные независимые шаги, таймаут, `rerun`, сохранение шагов.
- Шина событий = журнал действий; реестры полей/шагов/аспектов/инструментов/агентов; флаги `FEATURES_OFF`/`FEATURES_ON`.
- Агентный харнесс: `runAgent` до 8 шагов, шлюз по правам, `submit` со схемой и проверками, `agent_step`, `LlmPort.chat` (Polza, tool_calls).
- Сервис заявок: переходы по таблице, подтверждение/назначение, продление срока, результат инженера, `waiting_applicant` при вопросах.

### Модули
| Модуль | Что делает |
|---|---|
| `extraction` | агент `intake`: поля с цитатами, справочники, CMDB, база знаний, проверки и ground |
| `priority` | приоритет по матрице impact × urgency, авария, массовость, критичная техника, сроки |
| `routing` | топ-3 исполнителя с объяснением и признаком «нужно подтверждение» |
| `knowledge` | полнотекстовый поиск без эмбеддингов, статья, чек-лист шагов, вопрос базе агентом |
| `emergency` | правила + мнение модели, чек-листы, уведомления дежурным, экран аварий |
| `applicant-profile` | рабочее место и техника из профиля, «гость» |
| `clarify-chat` | вопросы-карточки, ответы, «Не знаю», повторный разбор |
| `mass-incident` | склейка похожих заявок в инцидент, демо-всплеск |
| `quality` | `pnpm eval`: поля, выдуманные, авария, приоритет, исполнитель, статья, вопрос, траектория; экран «Качество ИИ» |
| `history-seed` | 600 синтетических заявок за 6 месяцев |
| `reports-dashboard` | О0: плитки, разрезы, SLA, тепловая карта, горячие точки |
| `report-*` | О1 смена, О2 горячие точки, О3 SLA, О4 нагрузка, О5 эффект ИИ, О6 пробелы базы, О7 аварии |
| `screenshot` | картинка → текст через `VisionPort` (пока заглушка), кнопка в чате |
| `applicant-feedback` | шаблон ответа заявителю, виджет в карточке |
| `ai-vs-manual` | замер К4: действия и время «вручную» против «с ИИ» |
| `reports-hub` | страница «Отчёты»: О1–О7, CSV, выводы |

### API
Вход cookie-сессией, `GET /api/meta`, `POST /api/appeals` (sync и `async`), SSE разбора и общий поток событий,
`GET /tickets`, `GET /tickets/:id`, `GET /tickets/:id/analysis`, правка поля, confirm, переходы с причиной,
продление срока, результат инженера, журнал, уведомления, настройки, `/transcribe`, `/screenshot`, `/profile`,
`/logout`, `/engineers`, `/events`, маршруты модулей под `/api/m/<id>`.

### Интерфейс — 15 утверждённых экранов
1. Обращение (чат) — живой разбор, вопросы-карточки, стикер, журнал работы ИИ (раскрывающийся).
2. Мои заявки — активные/закрытые, подтверждение выполнения.
3. Очередь — сводка, фильтры, живое обновление, превью, Enter.
4. Проверка — 4 шага, след «Нашёл → Сверил → Спросил → Вам», правка, топ-3, «Назначена».
5. Авария/массовость — таймер, чек-лист, хронология, демо-инцидент.
6. Инженер — задачи, диагностика, результат, продление, возврат.
7. Дашборд — периоды, плитки, график, тепловая карта, выводы.
8. Вход — роли и гость.
9. Профиль — место, техника, отдел, смена пользователя.
10. Голос/фото — фото/скриншот в чате; голос ограничен доступом к речи.
11. Журнал — фильтры, «было → стало», топ правок.
12. Исполнители — навыки, смены, загрузка, текущие задачи.
13. База знаний — поиск, статья, шаги, вопрос базе.
14. Качество ИИ — прогон набора и таблица.
15. С ИИ / без ИИ — две колонки, счётчик, время, итог.
Плюс страница «Отчёты» (О1–О7), светлая тема по умолчанию и тёмная вторым режимом, анимации по правилам.

## 5. Ограничения

- Голос через API недоступен на текущем ключе; фото проходит путь, но vision-адаптер — заглушка.
- Выгрузка отчётов — только CSV; О8 (прогноз) не делался; «ответить всем» — текст, без массовой рассылки.
- Профиль без телефона и предпочтений уведомлений — нет полей в данных.
- Покрытие `pg-store.ts`/`schema.ts` — 0 % (нужна живая PostgreSQL); общее выше 60 %.
- В рабочем дереве есть незакоммиченные изменения (задача 2 Sonar и 035 журнал ИИ, плюс параллельный редизайн UI);
  финальный `pnpm check` может падать на тесте иконок тёмной темы из параллельной ветки.

## 6. Как запустить

```bash
docker compose up -d --build          # http://localhost:5173
pnpm check
pnpm test:coverage
pnpm demo:check
pnpm eval
docker compose --profile sonar up -d sonar && pnpm sonar
```
