## Что требует заказчик (кратко)

1. **Единая карточка сюжета** со статусной моделью: заявка → съёмка → в работе → текст готов → монтаж → проверка → утверждено → в эфире.
2. **8 ролей** (+ водитель как ресурс): администратор-продюсер, журналист, телеоператор, редактор,
   шеф-редактор, монтажёр, режиссёр монтажа, выпускающий режиссёр.
3. **Стек обязателен:** Docker + PostgreSQL.
4. **Безопасность и интеграции:** аудит действий, 152-ФЗ (данные в РФ), адаптерный слой для
   интеграций (аутентификация, монтажные станции NLE, внешние источники, уведомления, хранилище), SLA 99.5%.

Критерии кейса (5): статусная модель и роли · Docker + PostgreSQL · интеграции и безопасность ·
UX/UI карточки · работоспособность демо.

**Вывод:** одному — не успеть. С 3–4 параллельными агентами — **успеваем**: модули (планирование,
монтаж, эфир, уведомления) почти не зависят друг от друга, если сначала зафиксировать общий
контракт — схему БД, статусы и права. Кейс делится на потоки даже лучше, чем кейс 8.

Риск — **демо**: 8 ролей за 5–7 минут не показать по очереди. Решение — один сквозной сюжет:

## Демо и сценка «Я один — вся редакция»

1. Денис — продюсер: создаёт заявку «Прорыв трубы на Ленина», система подбирает группу и машину.
2. Переключается в «оператора» — загружает материал; в «журналиста» — ИИ расшифровывает интервью, пишет черновик.
3. «Редактор» возвращает на доработку → уведомление в Telegram звенит на телефоне.
4. Экран делится на 4 окна ролей: карточка в реальном времени едет по статусам у всех сразу.
5. Финал — режим «Аппаратная»: таймер до эфира, все элементы зелёные, суфлёр следует за голосом Дениса.
6. Слайд «Команда 1+∞»: один человек + агенты закрыли 8 ролей — тот же посыл, что у продукта.

Можно усилить реквизитом: при смене роли Денис меняет «атрибут» (наушники монтажёра, кепка оператора).
