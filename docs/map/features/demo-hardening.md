# Карта фичи: стабильное демо (022)

Статус: active
Дата: 2026-11-14
Связано: [../README.md](../README.md), [../../tasks/022-demo-hardening.md](../../tasks/022-demo-hardening.md), [../../hackathon/demo-script.md](../../hackathon/demo-script.md), [../../knowledge/environments.md](../../knowledge/environments.md), [../../specs/case9-core.md](../../specs/case9-core.md#7-стабильное-демо)

Смоук демо-сценария: перед защитой одна команда проходит весь путь по HTTP и говорит,
жив ли стенд. Кэша ответов модели и офлайн-режима нет (решение владельца 2026-11-14).

## Что добавилось

| Где | Что |
|---|---|
| `scripts/demo-check.ts` | смоук: 10 проверок пути защиты по публичным маршрутам API, чек-лист ✅/❌/⚠️/⏭️, код выхода 1 при провале |
| `package.json` | скрипт `demo:check` = `tsx scripts/demo-check.ts` |
| `docs/hackathon/demo-script.md` | точные команды подготовки, замеры прогона, что делать при сбое |
| `docs/knowledge/environments.md` | раздел «Демо-стенд»: Compose, запасная копия, `AI_MODE`, сброс |

## Как пользоваться

```bash
docker compose up -d --build
curl -s http://localhost:3001/api/health
pnpm demo:check                    # облако: 50–90 с, живая модель
pnpm demo:check --stub             # без ключа: 1–3 с, проверки модели пропускаются
pnpm demo:check --base-url http://<сервер>:3001
pnpm demo:reset                    # вернуть базу в исходное состояние (см. ограничения)
```

Скрипт в базу напрямую не пишет и код приложения не импортирует: только `fetch` к API,
как браузер. Cookie сессии получает через `POST /api/session`, роли берёт из `GET /api/users`
(заявитель — Денис Соколов, диспетчер, инженер и руководитель — первые с нужной ролью).

## Что проверяется

| # | Проверка | Как |
|---|---|---|
| 1 | API живой | `GET /api/health` → `status: ok`; при провале сразу выход 1 с подсказкой |
| 2 | Модули включены | `GET /api/meta`: `extraction`, `priority`, `routing`, `emergency`, `knowledge`, `mass-incident`, `report-shift`, `reports-dashboard` |
| 3 | Режим ИИ | `aiMode` из `/api/meta`: без ключа и без `--stub` — провал (на защите нужна живая модель) |
| 4 | Пользователи и вход | `GET /api/users` ≥ 30 и роли applicant / dispatcher / engineer / manager; вход каждым |
| 5 | Обращение и разбор | текст заказчика → `cabinet=312`, `equipment` (или `model`) — принтер HP, приоритет из справочника; если заявка ждёт ответа — «не знаю» на первую карточку |
| 6 | Статья и приоритет модели | `knowledge` не пуст (статья в разборе); приоритет `high`/`emergency` — иначе ⚠️ (в облаке приходит `medium`) |
| 7 | Диспетчер | `GET /api/tickets` не пуст, `POST /api/tickets/:id/confirm` → `assigned` с выбранным инженером |
| 8 | Уведомление инженеру | `GET /api/notifications` у назначенного: строка с `ticketId` (событие `ticket.assigned`) |
| 9 | Авария | «идёт дым, пахнет горелым» → `analysis.emergency.level !== 'none'` и `ticket.isEmergency = true` |
| 10 | Отчёты | `POST /api/m/report-shift/run` (руководитель) и `GET /api/m/mass-incident/incidents` (диспетчер) |

## Замеры (2026-11-14, локальный Compose)

| Прогон | Итог | Время |
|---|---|---|
| `--stub` (без ключа) | ✅ 9, ⏭️ 1 | 0,3 с |
| облако Polza | ✅ 9, ⚠️ 1 (приоритет `medium`, не `high`) | 50 с |

Облачный прогон: разбор 17–28 с, авария 17 с, отчёт смены 5 с; вывод модели в отчёте —
`source: ai`. На заглушке статью базы знаний и приоритет модели не проверяем: агентский
разбор без ключа не работает, поля даёт модуль-образец по правилам.

## Ограничения и что осталось

- **`pnpm demo:reset` падает**: `RESET_TABLES` в `packages/db/src/seed/index.ts` содержит `ai_cache`,
  таблицы нет с момента отказа от кэша → `relation "ai_cache" does not exist`. Нужна правка одной
  строки (убрать `ai_cache`, добавить `incident` и `agent_step`, чтобы сбрасывать инциденты и следы агента).
  Пока обходной путь — `docker compose down -v && docker compose up -d --build`.
- **Смоук оставляет следы**: два обращения и назначение. Несколько прогонов подряд на одном месте
  и корпусе склеиваются шагом массовости в инцидент и поднимают приоритет до `emergency` —
  поэтому после проверки база сбрасывается.
- **Приоритет в облаке — средний**: модель не заполняет влияние и срочность для текста про принтер;
  в демо показывать фактическую полоску или задавать карточку «Сколько сотрудников затронуто?».
- **Запасная копия не проверена**: адрес ❓ у владельца; на ней тот же смоук с `--base-url`.
- **Три прогона подряд** на облаке не зафиксированы (один прогон и один смоук на заглушке);
  критерий задачи «три раза без сбоев» закрывается владельцем перед защитой по чек-листу.
