Веб-часть `dispatcher-review`: очередь заявок и карточка проверки. Серверные маршруты уже есть —
см. [dispatcher-api.md](dispatcher-api.md). Интерфейс ничего не считает сам, кроме фильтров и группировки.

## Что сделано

| Где | Что |
|---|---|
| `modules/dispatcher-review/web/index.ts` | страница `/queue` для ролей `dispatcher`, `manager`, `admin`; одна строка в `modules/registry.web.ts` |
| `modules/dispatcher-review/web/QueuePage.tsx` | очередь: фильтры по статусу, аварийности и поиск, таблица, пустое состояние, ошибка API |
| `modules/dispatcher-review/web/TicketCard.tsx` | карточка заявки: группы полей, уверенность, цитата, след, правка, подтверждение, журнал |
| `modules/dispatcher-review/web/format.ts` | чистые функции: фильтры, группировка полей, подсветка цитат, журнал, «почему приоритет» |

## Очередь

- `GET /api/tickets?limit=100` — номер, статус, приоритет, категория, место, время.
- Фильтры считаются локально (`filterTickets`): статус, «только аварии», поиск по номеру и категории.
- Корпус и кабинет берутся из полей заявки: `GET /api/tickets/:id` для первых 24 строк.
  Пока деталь не загрузилась, в колонке «Место» стоит «загружаем…» — таблица не ждёт.
- Клик по строке (или Enter/Space) открывает карточку рядом с таблицей; повторный клик по «← К очереди» закрывает.
- Аварийные строки помечены красной полосой, приоритет — бейджем с пульсирующей точкой.

## Карточка заявки

| Блок | Источник |
|---|---|
| шапка: номер, категория, статус, приоритет, исполнитель | `GET /api/tickets/:id` → `ticket` |
| группы полей (классификация, место, оборудование, техника, симптомы) | реестр `GET /api/meta` → `fields` |
| уверенность и «на проверку» | `TicketField.confidence`, `needsReview` |
| цитата «почему ИИ так решил» | `TicketField.quote.text`, компонент `QuoteChip` |
| происхождение поля (текст / спросили / профиль / база / человек / не нашли) | `TicketField.origin`, компонент `OriginBadge` |
| «почему такой приоритет» | `priorityReason`: авария или поля `impact` и `urgency` |
| оригинал обращения с подсветкой цитат | `Appeal.originalText` + `highlightQuotes` |
| журнал действий | `GET /api/tickets/:id/events` → `Timeline` |

Правка и подтверждение — настоящие вызовы API, права проверяются на сервере:

- `PATCH /api/tickets/:id/fields/:key` — кнопка «Сохранить поле»; править можно только существующее поле
  (сервер обновляет строку `ticket_field`, а не создаёт новую). После ответа поле перерисовывается,
  журнал перечитывается.
- `POST /api/tickets/:id/confirm` — селект инженера из `GET /api/users` (роль `engineer`) и кнопка
  «Подтвердить и назначить». Доступна в статусе `in_review` и при праве `tickets.confirm`.
- Кнопки правки и подтверждения скрыты для ролей без прав (`hasPermission` из `@ugra/contracts`).
- Ошибка API показывается плашкой, кнопка «Обновить» перезагружает карточку.

## Дизайн

- Все цвета, шкала уверенности, шапки групп и журнал — из `@ugra/ui`; своих цветов модуль не задаёт.
- Сомнительные поля (низкая уверенность или `needsReview`) подсвечены жёлтой левой полосой и идут первыми
  в своей группе — диспетчер видит их без прокрутки.
- Уверенная заявка читается зелёным: бейдж «Решена/Закрыта» и шкала `ConfidenceBar` в зелёной зоне.
- Раскладка: таблица и карточка рядом на широком экране, в столбик — на узком.

## Как запустить

```bash
pnpm dev:api
pnpm dev:web
```

1. Войти диспетчером (например, «Анна Миронова»).
2. Открыть `#/queue`.
3. Выбрать заявку → проверить поля по цитатам → сохранить правку → назначить инженера.
4. Журнал действий обновится после подтверждения.

## Проверки

```bash
npx tsc --noEmit
npx vitest run apps/web
npx vite build --config apps/web/vite.config.ts
```

- `apps/web/tests/dispatcher-format.test.ts` — фильтры (успех и пустая очередь), группировка полей,
  подсветка цитат, журнал (известные и неизвестные события), причина приоритета.
- Страница не падает при выключенном модуле: `dispatcher-review` просто не попадает в меню
  и слоты (список включённых — из `/api/meta`).
- Пустая очередь и ошибка API имеют отдельные состояния с кнопками сброса и обновления.
