Веб-часть `dispatcher-review`: очередь заявок и карточка проверки. Серверные маршруты уже есть —
см. [dispatcher-api.md](dispatcher-api.md). Интерфейс ничего не считает сам, кроме фильтров, сортировки,
сроков регламента и журнала. Внешний вид — по утверждённому дизайну [case9-ui-design.md](../../specs/case9-ui-design.md).

## Что сделано

| Где | Что |

| `modules/dispatcher-review/web/TicketCard.tsx` | карточка: вкладки «Поля»/«Журнал», правка, подтверждение, клавиатура, «возвращена инженером» |

| `modules/dispatcher-review/web/parts.tsx` | `PriorityBars` (4 полоски), `DeadlineChips` (реакция и решение), `Kbd` |

| `modules/dispatcher-review/tests/format.test.ts` | тесты чистых функций: успех и границы |

## Очередь

- `GET /api/tickets?limit=100` — номер, статус, приоритет, категория, место, сроки.
- **Сортировка** (`sortTickets`): авария → критическая → высокий → средний → низкий; внутри уровня — по
  ближайшему сроку (`reactDueAt` или `slaDueAt`), заявки без срока — в конце; при полном равенстве старые раньше.
  Просроченные оказываются сверху сами, потому что их срок раньше всех.
- **Сроки по регламенту** (`ticketDeadlines`): две плашки «реакция 12 мин» и «решение 2 ч»; меньше 15 минут —
  жёлтая, просрочка — красная с пульсом. Таймер пересчитывается каждые 30 с (`useNow`).
- **Приоритет** — четыре вертикальные полоски (дизайн 3.4), слово только в подсказке и в шапке карточки;
  у критического и аварии полоски красные. Цвета — токены `--color-text` / `--color-danger`.
- **Сводка** — четыре плитки `StatTile`: ждут проверки, ждут заявителя, в работе, аварийных.
- **Живое обновление**: сервер пока не отдаёт общий поток событий (`GET /api/events/stream` не реализован),
  поэтому очередь опрашивается раз в 15 с; новые и изменившиеся строки подсвечиваются и «въезжают» сверху.
  Когда маршрут появится — заменить опрос на `EventSource` в одном месте (`LIVE_REFRESH_MS` в `QueuePage.tsx`).
- Фильтры считаются локально (`filterTickets`): статус, «только аварии», поиск по номеру и категории.
- Корпус и кабинет берутся из полей заявки: `GET /api/tickets/:id` для первых 24 строк.
- Клик по строке (или Enter/Space) открывает карточку; аварийные строки — с красной полосой слева.

## Карточка заявки

| Блок | Источник |
|---|---|
| шапка: номер, категория, статус, приоритет, исполнитель, сроки | `GET /api/tickets/:id` → `ticket` |
| вкладка «Поля»: группы (классификация, место, оборудование, техника, симптомы) | реестр `GET /api/meta` → `fields` |
| уверенность, «на проверку», цитата, происхождение поля | `TicketField.confidence`, `needsReview`, `quote`, `origin` |
| «исправил диспетчер · ИИ предлагал «…»» | `origin: human` + `aiValue` |
| «Почему такой приоритет» | `priorityReason`: авария или поля `impact` и `urgency` |
| оригинал обращения с подсветкой цитат | `Appeal.originalText` + `highlightQuotes` |
| «Итог заявки» справа: приоритет, категория, сроки, исполнитель, сколько полей проверить | `ticket` + `fields` |
| вкладка «Журнал» | `GET /api/tickets/:id/events` |
| плашка «Возвращена инженером: причина» | последний `ticket.returned` с `reason` (`lastReturn`) |

Правка и подтверждение — настоящие вызовы API, права проверяются на сервере:

- `PATCH /api/tickets/:id/fields/:key` — кнопка «Сохранить поле». Для поля-справочника значение выбирается
  из списка (`/api/meta` → `dictionaries`), для остальных — ввод. Сервер сохраняет `aiValue` и пишет
  `ticket.field.corrected`; после ответа поле и журнал перечитываются.
- `POST /api/tickets/:id/confirm` — селект инженера из `GET /api/users` (роль `engineer`) и кнопка
  «Подтвердить и назначить»; **без инженера кнопка disabled** и рядом подсказка. Доступна в статусе `in_review`
  и при праве `tickets.confirm`.
- Ошибка сервера — заметная плашка `role="alert"` над вкладками с кнопкой «Повторить» (повторяет то же действие).
- Пустые состояния: пустая очередь, «под фильтры не подошло», пустой журнал, «по типу событий нет».

## Клавиатура

| Клавиша | Что делает |
|---|---|
| `Tab` | ходит только по спорным полям (`needsReview`): остальные строки полей имеют `tabIndex=-1` |
| `Enter` в спорном поле | открывает правку этого поля (для справочника — список) |
| `Enter` в карточке | подтверждает и назначает выбранного инженера (`POST /confirm`) |
| `Esc` | закрывает карточку; в поле правки и списке — отменяет правку |

Подсказка «Enter — подтвердить, Tab — только спорные поля» стоит в строке вкладок и в очереди.

## Журнал

- Строки «ИИ предложил → человек исправил»: `diffValues` сравнивает `payload.previous` (значение ИИ) с
  `payload.value` и подсвечивает только отличающиеся фрагменты (`<mark>` в двух тонах).
- У каждой строки: тип события (бейдж), время, автор (имя из `GET /api/users`, иначе «ИИ / Человек / Система»),
  подпись поля из реестра; у `ticket.returned` — причина.
- События новее — выше. Фильтр по типу события (`journalTypes` + `filterJournal`), счётчики в вариантах.

## Дизайн

- Только светлая тема: свои цвета модуль не задаёт, всё через токены `@ugra/ui` (перекраска темы — в `packages/ui`).
- Приоритет — индикатор полосками, статусы — бейджи словами; ключевое в текстах — `<strong>`, без «маркера».
- Карточки — компонент `Card` (стекло), кнопки — `Button` (графитовая главная), никаких свечений и красных фонов.
- Анимации: появление строки очереди сверху со вспышкой, пульс просрочки; всё отключается
  при `prefers-reduced-motion`.
- Раскладка: таблица и карточка рядом на широком экране, в столбик — на узком.

## Как запустить

```bash
pnpm dev:api
pnpm dev:web
```

1. Войти диспетчером (например, «Анна Миронова»).
2. Открыть `#/queue`: сверху аварии и просроченные, у строк — сроки реакции и решения.
3. Выбрать заявку → `Tab` по жёлтым полям → поправить поле → выбрать инженера → `Enter`.
4. Открыть вкладку «Журнал»: правка видна как «ИИ предложил → человек исправил», фильтр по типу.

## Проверки

```bash
npx tsc --noEmit
npx vitest run modules/dispatcher-review apps/web
npx vite build --config apps/web/vite.config.ts
npx eslint modules/dispatcher-review
```

- `modules/dispatcher-review/tests/format.test.ts` — 34 теста: сортировка (аварии, равные приоритеты, без срока,
  битые даты), форматирование длительности и границы, сроки (нет данных, просрочка, «ровно сейчас»),
  дифф значений, журнал (правка, подписи справочников, порядок, мусор), фильтр по типу, возврат инженером,
  список спорных полей.
- `apps/web/tests/dispatcher-format.test.ts` — прежние тесты модуля, не сломаны.
- Страница не падает при выключенном модуле: `dispatcher-review` просто не попадает в меню и слоты.

## Осталось (задача 010)

- Общий поток событий `GET /api/events/stream` (SSE) вместо опроса раз в 15 с — серверная задача.
- Быстрые фильтры «Сомнительные / Готовые» из дизайна 4.3: нужен признак «есть спорные поля» в строке списка
  (`GET /api/tickets` его не отдаёт) — серверная задача.
- Стикер-превью справа и 4 блока-шага проверки (дизайн 4.3–4.4) — задача оболочки, не 010.
- Виджеты слотов `queue.toolbar` и `ticket.banner` от других модулей (авария, массовость, история оборудования).
