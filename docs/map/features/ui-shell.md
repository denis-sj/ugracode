## Шапка и роли (3.1)

Одна шапка: слева «Диспетчерская», по центру капсула-меню, справа круглые кнопки и аватар с инициалами.
Вкладки и кнопки зависят от роли:

| Роль          | Вкладки                                                             | Кнопки                       |
| ------------- | ------------------------------------------------------------------- | ---------------------------- |
| Заявитель     | Обращение · Мои заявки                                              | история, уведомления, аватар |
| Диспетчер     | Очередь (счётчик) · Аварии (красный счётчик) · Журнал · Исполнители | уведомления, аватар          |
| Инженер       | Мои задачи (счётчик) · База знаний                                  | уведомления, аватар          |
| Руководитель  | Дашборд · Отчёты · Качество ИИ                                      | уведомления, аватар          |
| Администратор | Очередь · Аварии · Журнал · Исполнители · Дашборд                   | уведомления, аватар          |

Счётчики очереди, аварий и задач считаются из `GET /api/tickets`; ошибка загрузки не ломает шапку.
Вкладка без зарегистрированной страницы показывает заглушку — страницу подключает свой модуль.

## Уведомления (3.2)

Колокольчик — не страница, а выпадающий блок под кнопкой: список, непрочитанные подсвечены,
«Прочитать все» вызывает `POST /api/notifications/:id/read` для каждого непрочитанного.
Закрывается кликом мимо и по Escape; ошибка API показывается текстом, а не скрывает уведомления.

## История обращений (3.3)

Кнопка-список у заявителя открывает панель справа поверх страницы: поиск, группы «Активные» и «Ранее»,
номер, дата и статус цветным текстом. Данные — `GET /api/tickets` (сервер уже отдаёт только свои заявки).
Закрывается крестиком, кликом по затемнению и по Escape.

## Токены и стиль

- Единственный источник цветов и анимаций — `packages/ui/src/tokens.css`.
  Модулям запрещены свои цвета и «сырые» значения длительностей.
- Подключение: `apps/web/src/main.tsx` импортирует `@ugra/ui/tokens.css` и `@ugra/ui/styles.css`;
  псевдонимы заданы в `apps/web/vite.config.ts` и корневом `tsconfig.json`.
- Тема одна — светлая: фон `#F5F6FB`, текст `#0F1222 / #5B6178 / #8A90A6`, акцент `#5A49E0`.
- Стекло: `--glass-card` (белый градиент .8→.58), `--glass-blur` (20 px, saturate 160 %),
  `--glass-inset` (внутренняя обводка), `--shadow-card`; у шапки — `--glass-liquid`.
- Кнопки: главная — графит `--color-graphite` (hover `--color-graphite-hover`), второстепенная —
  прозрачная с `--ring-inset`; градиентных кнопок и свечения нет.
- Статусы — точка/текст/тонкая линия: `--color-ok`, `--color-warn`, `--color-warn-bright`,
  `--color-info`, `--color-danger`.
- Приоритет (3.4) — `PriorityBars`: четыре полоски 4 px, закрашенные графитом, у критического/аварии — красным;
  слово только в `aria-label`/подсказке.
- Анимации: `ugra-rise` 0,4 с, `ugra-drawer` 0,35 с, `ugra-sticker`, плавная шкала, вспышка новой строки
  (`ugra-row-flash`). `prefers-reduced-motion` отключает всё.
- Атмосфера: `ugra-ambient` — три размытых пятна; на экране обращения добавляется сетка 80 px.

## Примитивы экранов (033)

| Компонент | Зачем |
|---|---|
| `ProgressScale` | шкала «Собрана → Проверена → Назначена → Выполнена»: 4 сегмента, `stageSegments` обрезает значения и переживает `NaN`; подписи — по флагу |
| `DetailRow` | пара «подпись → значение» в стикере (`layout="stack"`), итоге проверки и шапке аварии; тон значения — `ok/warn/danger/accent/muted` |
| `Modal` | окно «Заявка назначена»: Escape, клик по затемнению, фокус в панель |
| `Toast` | короткая ошибка действия внизу экрана, закрывается сама |
| `SearchField` | поиск в очереди и истории: лупа, прозрачный ввод, подпись для скринридера |
| `EmptyState` | пустая очередь/история: заголовок, объяснение, действие |
| `Timer` и `useElapsed` | таймер аварии и SLA; `formatElapsed` даёт `0:07`, `3 ч 26 мин`, отрицательное время — ноль |
| `InsightBlock` | «Что это значит» / «Что сделать» под графиками дашборда и отчётов |
| `ActionCounterPill` | «Ваших действий: N» в карточке проверки (К4) |

Шкала этапов исправлена: `in_review` закрашивает два сегмента (заявка проверена ИИ), `assigned` — три
(диспетчер назначил), `in_progress` остаётся на третьем до фактического выполнения. Тесты — на все статусы
и границы (`0…4`, отрицательное, `NaN`, своё число сегментов).

## Маршруты

- Роутинг — hash (`#/chat`, `#/tickets`, `#/queue`), без React Router. Неизвестный путь уводит
  на первую вкладку роли. `#/profile` — заглушка профиля (состав ещё не утверждён).
- Страницы берутся из `modules/registry.web.ts`: `defineWebModule({ pages })`.
  Выключенный модуль не попадает в меню, потому что его страницы не регистрируются.
- `GET /api/meta` также даёт реестр полей и справочники — из них строятся вопросы чата.

## Как запустить

```bash
pnpm dev:api     # API на http://localhost:3001
pnpm dev:web     # веб на http://localhost:5173
```

1. Выбрать пользователя.
2. Заявитель → `#/chat`; диспетчер → `#/queue`.
3. Если API не запущен, показывается светлый экран «API не отвечает» с кнопкой обновления.
