Общая оболочка веб-приложения и дизайн-система. Экран заявителя — [clarify-chat-ui.md](clarify-chat-ui.md),
очередь диспетчера — [dispatcher-review-ui.md](dispatcher-review-ui.md).

Источник правды по внешнему виду — [case9-ui-design.md](../../specs/case9-ui-design.md), раздел 2.
**Светлая тема — по умолчанию; тёмная — второй режим** (раздел 2.4): переключатель луна/солнце в шапке,
значения токенов — в `html[data-theme="dark"]`. Класс `.theme-dark` не используется, системную тему
(`prefers-color-scheme`) не включаем.

## Шапка и роли (3.1)

Меню — вариант E «Вдавленное стекло с иконками»: иконка над подписью (`apps/web/src/shell/TabIcon.tsx`, имя иконки — поле `icon` вкладки в `lib.ts`), активная вкладка вдавлена (`.shell-tab--on`: внутренняя тень, `--color-accent-strong`), счётчик — круг рядом с подписью. Новая вкладка = новая запись в `TABS` с `icon` + контур в `TabIcon.tsx`.

Одна шапка: слева «Диспетчерская», по центру капсула-меню, справа круглые кнопки и аватар с инициалами.
Вкладки и кнопки зависят от роли:

| Роль          | Вкладки                                                             | Кнопки                       |
| ------------- | ------------------------------------------------------------------- | ---------------------------- |
| Заявитель     | Обращение · Мои заявки                                              | история, уведомления, аватар |
| Диспетчер     | Очередь (счётчик) · Аварии (красный счётчик) · Журнал · Исполнители | уведомления, аватар          |
| Инженер       | Мои задачи (счётчик) · База знаний                                  | уведомления, аватар          |
| Руководитель  | Дашборд · Отчёты · Качество ИИ                                      | уведомления, аватар          |
| Администратор | Очередь · Аварии · Журнал · Исполнители · Дашборд                   | уведомления, аватар          |

Счётчики очереди, аварий и задач считаются из `GET /api/tickets`; ошибка загрузки не ломает шапку.
Вкладка без зарегистрированной страницы показывает заглушку — страницу подключает свой модуль.

## Уведомления (3.2)

Колокольчик — не страница, а выпадающий блок под кнопкой: список, непрочитанные подсвечены,
«Прочитать все» вызывает `POST /api/notifications/:id/read` для каждого непрочитанного.
Закрывается кликом мимо и по Escape; ошибка API показывается текстом, а не скрывает уведомления.

## История обращений (3.3)

Кнопка-список у заявителя открывает панель справа поверх страницы: поиск, группы «Активные» и «Ранее»,
номер, дата и статус цветным текстом. Данные — `GET /api/tickets` (сервер уже отдаёт только свои заявки).
Закрывается крестиком, кликом по затемнению и по Escape.

## Токены и стиль

- Единственный источник цветов и длительностей — `packages/ui/src/tokens.css`.
- Анимации блоков, списков, окон — `packages/ui/src/motion.ts` (GSAP, AutoAnimate, Motion, canvas-confetti), подключены в `apps/web/src/App.tsx` через `useBlockMotion`. Правила — [animations.md](../../rules/animations.md).
  Модулям запрещены свои цвета и «сырые» значения длительностей.
- Подключение: `apps/web/src/main.tsx` импортирует `@ugra/ui/tokens.css` и `@ugra/ui/styles.css`;
  псевдонимы заданы в `apps/web/vite.config.ts` и корневом `tsconfig.json`.
- Светлая тема (по умолчанию): фон `#F5F6FB`, текст `#0F1222 / #5B6178 / #8A90A6`, акцент `#5A49E0`.
  Тёмная — второй режим, значения ниже.
- Стекло: `--glass-card` (в светлой белый градиент .8→.58), `--glass-blur` (20 px, saturate 160 %),
  `--glass-inset` (внутренняя обводка через `--glass-edge`), `--shadow-card`; у шапки — `--glass-liquid`.
- Кнопки: главная — графит `--color-graphite` (hover `--color-graphite-hover`), второстепенная —
  прозрачная с `--ring-inset`; градиентных кнопок и свечения нет. В тёмной теме главная кнопка
  светлая (`#F2F3FA`) с тёмным текстом — это те же токены, не отдельные правила.
- Статусы — точка/текст/тонкая линия: `--color-ok`, `--color-warn`, `--color-warn-bright`,
  `--color-info`, `--color-danger`.
- Приоритет (3.4) — `PriorityMark`: круг-доля 16 px (25/50/75/100 %), у критического и аварии красный;
  слово только в `aria-label`/подсказке. `PriorityBars` (полоски) оставлен для совместимости.
- Анимации: `ugra-rise` 0,4 с, `ugra-drawer` 0,35 с, `ugra-sticker`, плавная шкала, вспышка новой строки
  (`ugra-row-flash`). `ugra-rise` и `ugra-sticker` остаются для совместимости, но узлы, которые двигает
  GSAP, их не используют — иначе двойная анимация. `prefers-reduced-motion` отключает всё.
- Атмосфера: `ugra-ambient` — три размытых пятна; на экране обращения добавляется сетка 80 px.
  В тёмной теме пятна тише и темнее (`--blob-violet/blue/ice`), сетка почти не видна (`--grid-line`).

### Тёмная тема (2.4)

- Включение: `ThemeToggle` в шапке **слева от колокольчика** (на входе — плавающая кнопка справа
  сверху). Иконка: луна в светлой теме, солнце в тёмной. `aria-label="Тёмная тема"`, `aria-pressed`
  отражает режим.
- Состояние — атрибут `data-theme="dark"` на `<html>`; выбор хранится в `localStorage` под ключом
  `ugra.theme`. Это единственное место, где тема меняется вручную: экраны и модули своих цветов не знают.
- Светлая — по умолчанию. Системная тема не используется: без сохранённого выбора всегда светлая.
- Без вспышки: inline-скрипт в `apps/web/index.html` ставит атрибут до загрузки React; `initialTheme`
  читает атрибут раньше хранилища. Хранилище недоступно или значение битое — светлая тема, без ошибок.
- Значения: фон `#0B0D17`, текст `#F2F3FA / #B7BDD3 / #8A90A6`, стекло `rgba(26,29,50,.8→.58)`,
  обводка `--glass-edge` = `rgba(255,255,255,.08)`, тени `rgba(0,0,0,.4)`, акцент `#A99BFF`,
  ссылки `#B3A6FF`, статусы `#3DD6A0 / #F5B84A / #5CB8FF / #FF7A59`.
- Правило для новых стилей: жёстких `#fff`, `#0F1222` и `rgba(...)` в CSS экранов нет; текст на цветной
  заливке — `--color-on-accent` (белый в обеих темах), на графитовой кнопке — `--color-graphite-contrast`.
- Плавность: `background-color/color/border-color` меняются за `--dur-base`; `prefers-reduced-motion`
  отключает переходы (общее правило в конце `styles.css`).

## Анимации по экранам

Правила и запреты — [animations.md](../../rules/animations.md). Точки входа:

- `useBlockMotion` один раз в `apps/web/src/App.tsx`: секции — прямые дети корня страницы
  (`.shell-main > * > *`), компоненты `@ugra/ui` и явные `data-reveal`. Секция-обёртка, внутри которой
  есть карточки или шаги, сама не въезжает — блоки появляются по отдельности.
- `useListMotion` — на родителе строк; включается, когда строки уже в DOM (`rows.length > 0`).
- CSS `@keyframes` — только бесконечные статусы (пульс аварии, «ИИ думает», скелетоны) и панели
  поверх страницы (уведомления, история), которые GSAP не трогает.

| Экран | Списки (`useListMotion`) | Блоки (`useBlockMotion`) | Ключевые события |
|---|---|---|---|
| Вход | — | шапка входа и панель выбора пользователя, группы пользователей | — |
| Обращение (чат) | — (сообщения приходят по одному через GSAP) | «Что случилось?», сообщения `chat-me`/`chat-ai`, карточка-вопрос (`key` меняется → новая анимация), стикер заявки | новые поля стикера (`data-reveal` на строке) |
| Мои заявки | список заявок `.tickets-list` | заголовок, карточка «подтвердите выполнение», список | смена вкладки «Активные/Закрытые» |
| История обращений | строки в `.history-drawer__body` | панель выезжает CSS (`ugra-drawer`) | фильтрация поиском |
| Уведомления | `.shell-notifications__list` | панель CSS (`ugra-pop`) | — |
| Очередь | `tbody` таблицы очереди | заголовок, тулбар, карточка списка, превью-стикер | новая/изменённая строка — вспышка `dr-row--fresh`; превью выбранной заявки |
| Проверка заявки | — | шапка, четыре `StepBlock`, карточки «Итог заявки» и «Сроки» | раскрытие шага (`expandBody`), шкала `ProgressScale`, окно «Заявка назначена» (`Modal tone="ok"` — пружина + конфетти) |
| Аварии и массовость | `.er-list__rows` | шапка, карточка списка, `er-hero`, регламент, хронология, массовость | «Объявить массовым» — `pulse` без конфетти; пульс `er-beat` — бесконечный CSS |
| Мои задачи | `.ed-list__items` | шапка, карточка задачи, диагностика, похожие, результат | новый результат/сообщение — CSS `ed-note` |
| База знаний | `.ed-kb__items` | карточка поиска, статья | смена статьи |
| Дашборд | `.rd-spots__table` (горячие точки) | заголовок, фильтры, пять плиток, карточки графиков и отчёта, сводка | период/фильтры перерисовывают плитки и графики |
| Профиль / заглушка | — | карточка профиля | — |

`Журнал` и `Исполнители` пока не зарегистрированы в `modules/registry.web.ts` — на их месте заглушка,
которая анимируется как обычная карточка.

## Примитивы экранов (033)

| Компонент | Зачем |
|---|---|
| `ProgressScale` | шкала «Собрана → Проверена → Назначена → Выполнена»: 4 сегмента, `stageSegments` обрезает значения и переживает `NaN`; подписи — по флагу |
| `DetailRow` | пара «подпись → значение» в стикере (`layout="stack"`), итоге проверки и шапке аварии; тон значения — `ok/warn/danger/accent/muted` |
| `Modal` | окно «Заявка назначена»: Escape, клик по затемнению, фокус в панель |
| `Toast` | короткая ошибка действия внизу экрана, закрывается сама |
| `SearchField` | поиск в очереди и истории: лупа, прозрачный ввод, подпись для скринридера |
| `EmptyState` | пустая очередь/история: заголовок, объяснение, действие |
| `Timer` и `useElapsed` | таймер аварии и SLA; `formatElapsed` даёт `0:07`, `3 ч 26 мин`, отрицательное время — ноль |
| `InsightBlock` | «Что это значит» / «Что сделать» под графиками дашборда и отчётов |
| `ActionCounterPill` | «Ваших действий: N» в карточке проверки (К4) |
| `PriorityMark` | приоритет кругом-долей (3.4): 25/50/75/100 %, слово в `aria-label`; `PriorityBars` остаётся для совместимости |
| `Segmented` | сегментированный фильтр «Все / Сомнительные / Готовые / Аварии» с счётчиками |
| `Chip` | компактный чип-фильтр (категория, исполнитель, канал) |
| `Sticker` | стеклянная панель-превью: очередь справа, карточка рядом с чатом |
| `StepBlock` | сворачиваемый шаг проверки с номером/галочкой и итогом |
| `Checklist` | чек-лист регламента и диагностики: отметки и пояснения |

Шкала этапов исправлена: `in_review` закрашивает два сегмента (заявка проверена ИИ), `assigned` — три
(диспетчер назначил), `in_progress` остаётся на третьем до фактического выполнения. Тесты — на все статусы
и границы (`0…4`, отрицательное, `NaN`, своё число сегментов).

## Маршруты

- Роутинг — hash (`#/chat`, `#/tickets`, `#/queue`), без React Router. Неизвестный путь уводит
  на первую вкладку роли. `#/profile` — заглушка профиля (состав ещё не утверждён).
- Query из hash (`#/queue?status=in_review&emergency=true&assignee=u-1`, `#/review?id=…`) разбирается
  в `parseHash` и приходит странице в `WebPageProps.query`; очередь применяет его как начальные фильтры.
- Страницы берутся из `modules/registry.web.ts`: `defineWebModule({ pages })`.
  Выключенный модуль не попадает в меню, потому что его страницы не регистрируются.
- `GET /api/meta` также даёт реестр полей и справочники — из них строятся вопросы чата.

## Как запустить

```bash
pnpm dev:api     # API на http://localhost:3001
pnpm dev:web     # веб на http://localhost:5173
```

1. Выбрать пользователя.
2. Заявитель → `#/chat`; диспетчер → `#/queue`.
3. Если API не запущен, показывается светлый экран «API не отвечает» с кнопкой обновления.
