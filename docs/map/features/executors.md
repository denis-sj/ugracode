Статус: active

Экран диспетчера показывает, кто на смене, чем занят и что умеет, — эти же признаки ИИ учитывает
при подборе исполнителя. Только чтение: модуль работает на маршрутах API ядра, своих маршрутов нет.

## Маршруты API

| Что                   | Запрос                                               | Право          |
| --------------------- | ---------------------------------------------------- | -------------- |
| карточки исполнителей | `GET /api/engineers`                                 | `tickets.read` |
| задачи выбранного     | `GET /api/tickets?assigneeId=<id>&limit=20`          | `tickets.read` |
| подписи подразделений | `GET /api/meta` (`dictionaries` = `department`)      | `any`          |
| открыть заявку        | `#/review?id=<ticketId>` (переход внутри интерфейса) | —              |

## Чистые функции

| Функция                                        | Правило                                                                                                                                          |
| ---------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| `departmentLabel(dictionaries, id)`            | подпись из справочника `department`; неизвестный код остаётся, пусто → «Подразделение не указано»                                                |
| `gradeLabel(level)`                            | `first_line` → «Первая линия», `second_line` → «Вторая линия», `lead` → «Ведущий специалист»; неизвестный код не теряется, число → «N-й уровень» |
| `loadState(openTickets, threshold = 5)`        | шкала 0…100, `warn` на 4 при пороге 5, `danger` и «перегруз» с 5; мусор на входе → 0                                                             |
| `filterEngineers(engineers, filters, context)` | подразделение, «только на смене», поиск по имени, должности, навыкам, корпусам и подписи подразделения                                           |
| `sortEngineers(engineers, threshold = 5)`      | перегруженные → на смене → больше открытых заявок → имя; исходный массив не меняется                                                             |
| `skillChips(skills)`                           | код навыка → подпись, уровень подрезается к 1…5, дубли схлопываются по большему уровню                                                           |
| `taskDeadline(ticket, now)`                    | ближайший из `reactDueAt`/`slaDueAt`; `warn` ≤ 15 минут, `danger` при просрочке, нет дат → `null`                                                |
| `initials(fullName)`                           | «Игорь Лебедев» → «ИЛ»                                                                                                                           |

## Решения и ограничения

- **Порог перегруза 5** — правило интерфейса (`LOAD_THRESHOLD`), в API его нет; карточка показывает
  «N из 5 задач», чтобы цифра читалась без легенды.
- **«Сейчас в работе»** — фактические заявки из `GET /api/tickets?assigneeId`: закрытые и отменённые
  скрыты. Названия задач в выдаче отсутствуют, поэтому строка — номер, категория, статус, приоритет и срок.
- **Навыки** — коды из `data/engineers.json`; человеческие подписи лежат в `SKILL_LABELS` модуля,
  потому что справочника `skill` в `/api/meta` нет. Неизвестный код показывается как есть.
- **Подразделение** берётся из `dictionaries` (`department`); грейд — из поля `level`, справочник `level`
  в `/api/meta` не используется, чтобы подписи совпадали с дизайном («Первая линия», а не «1-я линия»).
- **Права:** экран доступен диспетчеру, админу и руководителю; роль `engineer` его не видит в меню
  (вкладка «Исполнители» есть только у диспетчера, дизайн 3.1).
