# Карта фичи: экран «Авария и массовость» и плашка карточки

Статус: active
Дата: 2026-11-14
Связано: [../README.md](../README.md), [../../specs/case9-ui-design.md](../../specs/case9-ui-design.md), [../../specs/case9-features.md](../../specs/case9-features.md), [../../hackathon/case9-brief.md](../../hackathon/case9-brief.md), [emergency.md](emergency.md), [dispatcher-api.md](dispatcher-api.md)

Веб-часть модуля `emergency`: страница `/incidents` (дизайн 4.5) и виджет `ticket.banner` для карточки
заявки. Авария — **красная пульсирующая точка, красный текст и тонкая линия**, без красного фона
([дизайн, раздел 1](../../specs/case9-ui-design.md#1-что-владелец-запретил-нейрослоп)).

## Откуда данные

| Блок | Источник |
|---|---|
| список аварий: номер, время, статус, возраст | `GET /api/tickets?isEmergency=true&limit=50` + `sortByRecent` |
| корпус/кабинет в списке и в шапке | поля заявки `building`, `cabinet`, `floor` из `GET /api/tickets/:id` (`placeFromFields`) |
| канал обращения и цитата с признаками | `GET /api/tickets/:id` → `appeal.channel`, `appeal.originalText`; признаки — `analysis.emergency.signs` |
| «почему авария», уверенность, чек-лист | `GET /api/tickets/:id/analysis` → `analysis.emergency` (`readEmergencyVerdict`) |
| хронология | `GET /api/tickets/:id/events` (право `tickets.events`) |
| ответственный | `GET /api/users` по `ticket.assigneeId` |
| список массовых сбоев | `GET /api/m/mass-incident/incidents` (`incidentCards`): номер, размер, корпус, категория, статус, время |
| карточка инцидента и его заявки | `GET /api/m/mass-incident/incidents/:id` (`readIncidentDetail`); активный — ручной выбор или `ticket.incidentId` |
| демо-всплеск | `POST /api/m/mass-incident/demo` (право `admin` по контракту маршрута) |
| столбики и счётчик | заявки инцидента из карточки; инцидента нет — `GET /api/tickets?limit=200` с фильтром категория + корпус + окно |

Окно и порог — настройки массовости (`massWindowMinutes` 15, `massThreshold` 5 в
`data/settings.json`), в интерфейсе это константы `MASS_WINDOW_MINUTES` и `MASS_THRESHOLD`.
`similarTickets()` повторяет правило локально: та же категория, тот же корпус, окно 15 минут,
закрытые/отменённые не считаются. `incidentWindowMinutes()` расширяет окно столбиков, чтобы
накрыть всё время жизни инцидента (не больше суток).

## Что видит диспетчер

- Слева список аварий: номер, время, место, статус, сколько ждёт. Свежие сверху, выбранная подсвечена акцентом.
- Справа шапка-карточка: пульсирующая красная точка, «Авария · № · канал», заголовок
  «категория · корпус/кабинет», цитата с жирными признаками, таймер с момента обращения,
  «Почему авария» (`signs` + `rulesMatched`), уверенность, ответственный, статус.
- Три карточки: **регламент** (чек-лист из `analysis.emergency.checklist`, отметки локальные, шкала прогресса),
  **хронология** (`Timeline`, авария — красная точка), **«Похоже на массовый сбой»**: рост счётчика,
  столбики по минутам, пунктирная линия порога, список инцидентов (номер, размер, корпус, категория,
  статус, время) и карточка выбранного инцидента с номерами заявок.
- Кнопка «Объявить массовым инцидентом»: администратор создаёт серверный демо-всплеск
  (6 похожих обращений, склейка в инцидент) — после ответа показывается номер, число заявок и статус,
  тост без конфетти («авария — не праздник»). Диспетчеру и остальным кнопка неактивна с подсказкой
  «Демо-всплеск доступен администратору»; право проверяет и сервер.
- Пустые состояния: «Аварий нет — это хорошо», «Массовых сбоев нет», «Выберите аварийную заявку слева»,
  «Регламент не задан», «Событий пока нет», «Недостаточно данных: не указан корпус или категория».

## Виджет `ticket.banner`

Два режима:

1. Карточка передала готовые пропсы `emergency` / `isEmergency` / `detectedAt` — рисуем сразу.
2. Передан только `ticketId` и `api` — виджет сам загружает `GET /api/tickets/:id/analysis` и
   `GET /api/tickets/:id` (флаг `isEmergency`) и рисует плашку.

Нет аварии — `null`, ничего не рисуется. Заявка помечена аварийной, а вердикта нет — «под вопросом»
без выдуманных признаков (`emergencyBanner()`).

## Клавиатура и доступность

- Строки списка и инцидентов — кнопки: `Tab` + `Enter`/`Space`, выбранный инцидент — `aria-pressed`.
- Пункты регламента — кнопки с `aria-pressed`; шкала прогресса — `role="progressbar"`.
- Столбики — `role="img"` с подписью «N за 15 минут, порог 5»; линия порога скрыта от скринридера.
- Тост — `role="status"` (ошибки — `role="alert"`); анимации отключаются при `prefers-reduced-motion`.

## Проверки

```bash
npx tsc --noEmit
npx vitest run modules/emergency
npx vite build --config apps/web/vite.config.ts
npx eslint modules/emergency
```

- 34 теста `emergency-ui.test.ts`: место, вердикт и «почему авария» (включая мусор и пустые данные),
  таймер и возраст, сортировка, похожие заявки (корпус/категория/окно/закрытые/битые даты),
  столбики и порог, цитаты, хронология, канал, инциденты API (`incidentCards`, `readIncidentDetail`),
  окно инцидента и права на демо-всплеск.
- Страница не падает без разбора (`404` анализа), без журнала событий и без маршрутов массовости:
  показывает пояснение и пустой список «Массовых сбоев нет».
- Проверено на живом API (`/api/m/mass-incident/incidents`, `/demo`, `/:id`): демо создаёт 6 обращений,
  склеивает их с уже похожими и отдаёт карточку с заявками. Визуальная проверка в браузере осталась:
  в сессии не было подключённого desktop-браузера.

## Чего не хватает на сервере

- **Название аварии** (как «Дым из принтера…» в макете) не хранится отдельным полем: заголовок собирается
  из категории и места, а текст обращения показывается цитатой.
- **Ответственный** — только `assigneeId`; статус «в пути» и телефон дежурного недоступны, кнопки
  «Позвонить дежурному» / «Сообщить начальнику» поэтому не рисуются.
- **Отметки регламента** не сохраняются: локальное состояние страницы.
- **«Ответить всем» одной кнопкой** в карточке инцидента пока текстом: маршрута массовой рассылки нет,
  одно сообщение уходит через виджет `ticket.footer` на странице проверки.
