## Слова владельца

- «Пусть deepseek-v4.1-flash будет использоваться для отчётов и разбора обращений. Ведь он самый лучший сейчас.»
- «RAG не является основным способом генерации ответов»; ответ — через управляемый цикл вызова инструментов
  (ReAct, до 8 шагов, шлюз выполнения по роли); «через evals реализовать харнесс + прогоны проверки настройки идеально сделать».
- Владелец прислал `.env`: `LLM_MODEL_MAIN=gpt-6-luna`, `LLM_MODEL_CHEAP=deepseek-v4.1-flash`, `EMBEDDINGS_MODEL=bge-m3`,
  `EMBEDDINGS_DIM=768`, `SPEECH_MODEL=gigaam-v3`, адрес `https://api.polza.ai/api/v1`.

## Что решили

1. Разбор обращения — агент `intake` с инструментами (CMDB, справочники, база знаний, похожие заявки), итог через `submit`
   со схемой. Код по-прежнему проверяет цитаты, считает приоритет и исполнителя; человек подтверждает.
2. Эмбеддинги и pgvector не используются; поиск — инструменты с полнотекстовым поиском.
3. Одна модель `deepseek/deepseek-v4.1-flash` в обеих переменных; замена — только по цифрам проверок.
4. Проверки (evals) — главный инструмент настройки: контрольный набор (10) и настроечный (30–40, ❓ подтвердить),
   оценщики кодом с порогами, цикл «прогон → разбор → одна правка → прогон».

## Замечания к `.env` владельца

- Имена моделей нужны с префиксом провайдера: `deepseek/deepseek-v4.1-flash`, `ai-sage/gigaam-v3`. Без префикса в каталоге их нет.
- `EMBEDDINGS_MODEL` и `EMBEDDINGS_DIM` можно оставить пустыми. (Для справки: у `baai/bge-m3` вектор 1024, не 768.)
