## Что сделать

1. Очередь заявок: фильтры, сортировка по приоритету и сроку SLA, живое обновление по SSE, таймер SLA.
2. Правка поля в одно действие (`PATCH /api/tickets/:id/fields/:key`), значение ИИ сохраняется в `ai_value`, событие `ticket.field.corrected`.
3. Tab прыгает только по полям «на проверку»; Enter — подтвердить и назначить (`POST /api/tickets/:id/confirm`).
4. Вкладка «Журнал»: события заявки, строки «ИИ предложил → человек исправил» с подсветкой отличий.
5. Права: правка и подтверждение — только диспетчер (проверка на сервере, тест на отказ другим ролям).
6. Тесты: успешный путь и каждая ветка ошибки; работа с выключенным флагом модуля.
7. `modules/<id>/README.md` и карта фичи в `docs/map/features/`.

## Критерии готовности

- **Работает в демо:** Диспетчер исправляет одно поле, жмёт Enter — заявка назначена, правка видна в журнале. Критерий К3.
- `pnpm check` зелёный, тест-контракт модулей проходит, с `FEATURES_OFF` этого модуля остальное работает.
- Нет новых замечаний SonarQube уровня Blocker / Critical / Major.
