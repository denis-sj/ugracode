## Что сделать

1. Аспект `emergency` для шага извлечения (мнение модели, признаки с цитатами).
2. Шаг `emergency.detect` (стадия `assess`): правила из `data/emergency-rules.json` + аспект → итог по таблице из спецификации; при сомнении — эскалация.
3. Событие `emergency.detected` → подписчик выбирает дежурного с нужным навыком (смена, дежурство) и шлёт уведомление через `NotificationPort`.
4. Веб: красный режим (`EmergencyOverlay`), заявка всплывает наверх очереди, чек-лист действий из регламента, виджет уведомлений в шапке.
5. Тесты: каждое правило; правила без модели и модель без правил; нет дежурного → уведомление руководителю.
6. Тесты: успешный путь и каждая ветка ошибки; работа с выключенным флагом модуля.
7. `modules/<id>/README.md` и карта фичи в `docs/map/features/`.

## Критерии готовности

- **Работает в демо:** «Не печатает принтер, и идёт дым» → красный режим и уведомление дежурному; «принтер не печатает» — обычная заявка. Случай «авария», ментор п. 5 и 9.
- `pnpm check` зелёный, тест-контракт модулей проходит, с `FEATURES_OFF` этого модуля остальное работает.
- Нет новых замечаний SonarQube уровня Blocker / Critical / Major.
