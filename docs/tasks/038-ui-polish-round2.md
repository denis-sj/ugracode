Принцип владельца: **кратко, минималистично, всё важное видно на одном экране, лишнее скрыто.** Новый пользователь
без объяснений должен понять, что перед ним. Делать после текущей ветки `feature/ui-redesign` (те же файлы).
Нумерация ниже = номера скриншотов владельца.

**Согласовано владельцем (2026-11-14) по макетам:** п. 1–5, 7–12 как описано ниже; п. 6 (шапка) — только увеличить правый блок.

## Экран «Обращение» (заявитель)

1. **Шаги разбора** (скрин 1). Сейчас «Обрабатываем обращение» повторяется дважды, и список виден сразу.
   Сделать как в ChatGPT: по умолчанию свёрнуто, одна строка «Разбираю обращение…» с текущим шагом; галочки и
   полный список — только после раскрытия. Дубли шагов убрать (одно название — один шаг). После завершения:
   «Разобрал за N с» (как сейчас, скрин 2).
2. **Поле ввода уезжает** (скрин 2). Когда чат растёт вниз, поле ввода пропадает за экран, а обращение «съезжает».
   Поле ввода закреплено внизу (sticky), лента сообщений прокручивается над ним и сама едет к последнему
   сообщению. Карточка вопроса («Сколько сотрудников затронуто?») и поле ввода всегда помещаются в экран.
3. **Лого в шапке** (скрин 3). Убрать иконку-квадрат. Остаётся только слово «Диспетчерская».
4. **Заявка готова** (скрины 4, 5). Правая панель «Ваше обращение» оформляется как **стикер**.
   - Пока заявка не отправлена и не подтверждена: стикера нет, чат по центру.
   - Когда заявка отправлена: стикер «прилипает» справа с анимацией (прилёт, лёгкий покачивающийся «шлёп»
     и затухающее покачивание, как бумажка, приклеенная к стене); к нему добавляется отметка «Отправлено ✓».
   - **Композиция не меняется:** чат остаётся на месте по центру, стикер занимает свободное поле справа и
     ничего не сдвигает. На узком экране стикер встаёт над полем ввода.
   - Стиль — токены сайта, светлая и тёмная темы. Анимация по [правилам](../rules/animations.md), без смены
     раскладки (только transform/opacity), уважать `prefers-reduced-motion` (без покачивания).
5. **Смена темы** (скрины 9, 10). При переключении светлая ↔ тёмная заголовок «Что случилось?» и поле ввода
   прыгают по вертикали (разные отступы). Раскладка не зависит от темы: меняются только цвета.
6. **Шапка** (скрин 11). Решение владельца: **ничего не перерисовываем, просто увеличиваем правый блок** (тема,
   уведомления, аватар, имя и роль), чтобы он был по высоте, радиусу, отступам и размеру шрифта в одном ряду с
   центральным блоком вкладок. Внешний вид блока (стеклянная «таблетка», разделитель, аватар слева) остаётся.
   Вариант «шапка из макета» владелец не принял.

## «Мои заявки» (заявитель)

7. **Простой номер заявки** (скрин 6, уточнено владельцем: прежний вид «3-20261114-0601» не нравится).
   Формат: **`№ 602`** — сквозной порядковый номер без даты и префиксов, одинаковый везде: очередь, аварии,
   журнал, «Мои заявки», стикер, уведомления, ответы ИИ. Номер выдаёт сервер при создании заявки (счётчик,
   уникальный, не переиспользуется); историческим заявкам сида присвоить номера по порядку создания. Если
   смена хранимого поля `number` слишком объёмна, допустимо временно хранить старый идентификатор и показывать
   новый через единую функцию форматирования (есть `packages/ui/tests/ticket-format.test.ts`), но целевой вариант
   — хранить и показывать один и тот же простой номер. Поиск по номеру принимает «602» и «№ 602».
8. **Статус** (скрины 7, 8). Статус («На проверке», «В работе») выводить **над полосками хода**, как подпись к ним.
   Из-под названия заявки статус убрать. Колонку «Исполнитель и срок» оставить.

## Профиль

9. **Блоки выходят за границы** (скрин 12): карточка «Ваша техника» — иконка и маркер-точка стоят отдельно,
   текст съехал. Иконка и название в одной строке, без точки-маркера, содержимое не вылезает из карточки.

## Диспетчер

10. **Очередь — доска карточек** (скрины 13, 14). Вместо таблицы и боковой панели: аккуратные карточки
    (название, короткий номер, уверенность, «что сделать», срок), разделённые отступами, колонки или сетка по
    статусам: «Сомнительные», «Готовые», «Аварии». Клик по карточке открывает **карточку-деталь** (раскрытие или
    выдвижная панель), в ней поля, предложение исполнителя и кнопки. На доске всё понятно с первого взгляда.
11. **Аварии** (скрины 15, 16). Сейчас экран перегружен и не помещается. Всё главное на одном экране: список слева,
    выбранная авария справа (причина, уверенность, ответственный, статус). Регламент, хронологию и «массовый
    сбой» — свёрнутыми блоками, раскрываются по клику. Лишнее скрыть. Подпись «Загружаем регламент…» не
    оставлять навсегда: пустое состояние — одной строкой.
12. **Журнал действий** (скрин 17).
    - Показывать **5 последних событий**, ниже «Показать ещё».
    - Убрать цветные точки перед именами.
    - Число «300» не показывать без подписи: «Всего событий: 300» либо убрать.
    - У таблицы есть заголовки колонок: «Когда», «Кто», «Что изменилось», «Заявка». Понятно для нового человека.
    - Блок «Что чаще исправляют» компактный или свёрнутый, не занимает место, когда правок нет.
    - Номер заявки в строке не обрезается (короткий формат из п. 7).

13. **Экран входа: одна учётка на роль** (решение владельца). Сейчас в списке 39 пользователей (22 заявителя,
    14 инженеров). На экране входа показывать четыре крупные карточки: **Заявитель, Диспетчер, Инженер,
    Руководитель** (плюс «Администратор» малой ссылкой), по одной готовой учётке на роль; клик входит сразу.
    Остальных пользователей с экрана входа убрать. Инженеры остаются в данных: на них держатся подбор
    исполнителя, загрузка и навыки (см. [037](037-staff-management.md)). Заявителей из истории оставить только
    если на них ссылаются заявки; иначе удалить. Для сценариев демо учётки: типовой заявитель, звонок ИИ-оператору
    и гость остаются доступными через «Ещё». Права ролей по-прежнему проверяются на сервере.

## Критерии готовности

- Все 13 пунктов проверены в браузере на светлой и тёмной теме, на 1440 и на узком экране.
- Каждый экран помещается без прокрутки при типичных данных (кроме лент: чат, журнал).
- Тесты: форматирование короткого номера, сворачивание шагов, закрепление поля ввода, появление стикера
  только после отправки.
- Нет новых замечаний SonarQube Blocker/Critical/Major; `python3 -m unittest discover -s tests` проходит.
