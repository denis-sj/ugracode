Поток Б. **Нужно к чекпоинту 1.** Папки: `packages/ui/`, `apps/web/`, `modules/clarify-chat/web/`,
`modules/dispatcher-review/web/`. Требование владельца: **очень красиво, анимации, «вау» на защите**.

## Что сделать

1. **`packages/ui`:** дизайн-токены (цвета, отступы, тени, длительности анимаций; светлая и тёмная тема),
   Tailwind-тема, компоненты `Card`, `Badge`, `Button`, `ConfidenceBar`, `QuoteChip`, `FieldRow`, `StatTile`,
   `Timeline`; анимации `flyToField`, `pulse`, `countUp` (Framer Motion); хук `useActionCounter`.
2. **Оболочка `apps/web`:** вход выбором пользователя (карточки пользователей по ролям), меню по роли из реестра
   страниц, слоты виджетов из раздела 3.8, индикатор контура ИИ в шапке (из `GET /api/meta`), подписка на SSE.
3. **Моковый API** (MSW) от схем `packages/contracts` — чтобы не ждать сервер. Переключение на настоящий API — переменной.
4. **Чат заявителя** (`modules/clarify-chat/web`): ввод обращения, **живой разбор** — шаги пайплайна идут по SSE,
   фрагменты текста подсвечиваются и «перелетают» в поля заявки справа; итог «Заявка № … принята, приоритет …».
   Карточки-вопросы (`buttons`, `select`, `text`, `location`) — компоненты готовы, логика ответов придёт в 009.
5. **Карточка заявки** (`modules/dispatcher-review/web`): поля по группам из реестра, шкала уверенности, цитата
   по наведению, подсветка полей «на проверку», след поля («найдено в тексте / спросили / диспетчеру»), приоритет
   с текстом «почему». Правка и подтверждение — в 010; здесь только показ.
6. Тесты компонентов (успех и пустые / ошибочные состояния), проверка, что страница не падает с выключенным модулем.
7. Карта: `docs/map/features/ui-shell.md`.

## Критерии готовности

- Выбрал заявителя → написал пример заказчика → видно анимацию разбора → заявка; выбрал диспетчера → открыл карточку.
- Работает и на моковом, и на настоящем API (после слияния 005 и 006).
- Цвета и анимации — только из токенов. `pnpm check` зелёный.
- **Работает в демо:** этот путь показываем на чекпоинте 1.
