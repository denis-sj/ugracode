Связано: [case9-core.md](case9-core.md), [../prompts/feature-intake.md](../prompts/feature-intake.md), [../hackathon/case9-brief.md](../hackathon/case9-brief.md)

Как пользоваться: скопировать блок ниже в `docs/specs/features/<id>.md` и заполнить. Не больше одной страницы,
10 минут. Точки расширения и рецепт — [case9-core.md](case9-core.md#11-как-добавить-фичу).

```markdown
# Фича: <название>

Статус: draft | approved | done
Дата: ГГГГ-ММ-ДД
Модуль: `modules/<id>/` · Флаг: `<id>` (по умолчанию выкл. / вкл.)
Связано: [../case9-core.md](../case9-core.md), <задача>

## Что делает
1–2 предложения: кто пользуется (заявитель / диспетчер / инженер / руководитель) и что получает.

## Зачем
Критерий К1–К5 / слова ментора / критерий экспертов, который закрывает. Нет такого — фича откладывается.

## Момент в демо
Когда и как показываем (секунды, что на экране). Нельзя показать — не делаем.

## Точки расширения
| Точка | Что добавляем |
|---|---|
| Поля (`fields`) | |
| Аспект извлечения (`aspects`) | |
| Шаги пайплайна (`steps`: id, стадия, читает, пишет, запасной путь) | |
| События: публикует / слушает | |
| Данные: таблицы, сид | |
| API (`/api/m/<id>/…`, право) | |
| Экраны: страницы, виджеты (слот) | |
| Отчёт | |
| Порты (какие использует; новая реализация?) | |

Пустые строки удалить. **Правка ядра или контрактов нужна? да / нет** — если да, описать отдельно, это отдельная задача.

## Файлы
Список файлов модуля. Чужие папки не трогаем; из общих — только по строке в `modules/registry.server.ts` и `modules/registry.web.ts`.

## Тесты
Успешный путь; каждая ветка ошибки; работа с выключенным флагом; эталон для оценщика (если есть).

## Размер и риск
S (до 1 ч) / M (1–3 ч) / L (больше). Чем грозит демо и как выключаем.
```
