## 3. Слайды

Правило: **одна мысль, одна большая цифра, подписи мелко, без абзацев**. Говорит человек, слайд показывает.
У каждой цифры мелко указан источник. Цифра без источника на слайд не попадает.

### 1. Титул
- «Диспетчерская с ИИ». Подзаголовок: «Обращение → готовая заявка. Последнее слово — за человеком».
- Кейс 9 · ООО «Газпром трансгаз Сургут» · команда «1+∞» · номинация Pro.
- Анимация: заголовок проявляется, фоновые пятна медленно смещаются (один раз, не бесконечно).

### 2. Боль
- Надпись «03:12 · ночная смена · диспетчер один».
- Пузырь обращения: «У меня опять ничего не работает».
- Чипы того, что делает диспетчер вручную: «перезвонить», «найти кабинет», «найти инженера»,
  красный — «не пропустить аварию».
- Сквозной персонаж — **принтер HP в корпусе Б, каб. 312** (пример заказчика): он же в демо и в отчёте.
- Анимация: чипы появляются каскадом (≤ 0,6 с).

### 3. Что сделали: К1–К5
Пять строк «требование заказчика → что сделано»:

| | Требование | Сделано |
|---|---|---|
| К1 | 5–10 тестовых обращений | 10 обращений с эталоном: типовые, аварии, нехватка данных, сленг, звонок |
| К2 | ИИ верно заполняет поля и исполнителя | `pnpm eval`: таблица «эталон / ИИ» по каждому полю |
| К3 | Диспетчер исправляет и подтверждает | Сомнительные поля подсвечены, правка, Enter, журнал «ИИ → человек» |
| К4 | Ручные действия с ИИ и без | Страница замера, реальный замер — слайд 6 |
| К5 | Стабильность и архитектура | Ядро + модули, порты, флаги фич, SonarQube без замечаний — слайд 7 |

- Анимация: строки появляются по одной, у каждой зажигается галочка.

### 4. Как работает
- Цепочка из шести шагов: **текст → поля с цитатами → приоритет по матрице → исполнитель → база знаний → человек подтверждает**.
- Три подписи под цепочкой:
  - «у каждого поля — цитата из текста и уверенность»;
  - «приоритет — по регламенту «влияние × срочность», а не по эмоциям»;
  - «не хватает данных → ИИ спрашивает заявителя карточкой → нет ответа → поле диспетчеру».
- Анимация: шаги загораются по очереди, по линии бежит точка.

### 5. Точность на 10 обращениях
- **Огромная цифра: «0» — пропущенных аварий.**
- Рядом две малые: «100 % — исполнитель в топ-3», «84 % — полей заполнил ИИ».
- Строка мелко: «где ИИ ошибается — 9 выдуманных полей; каждое подсвечено, без диспетчера заявка не уходит».
- Источник: «10 тестовых обращений · reports/quality.md · модель deepseek-v4.1-flash».
- Анимация: цифры досчитываются от нуля (count-up ≤ 0,9 с).

### 6. Польза в цифрах (главный слайд)
Три блока на одном слайде, появляются по нажатию кликера (три шага внутри слайда):

1. **С ИИ / без ИИ** (К4). Слева ускоренное видео ручного режима с бегущим таймером, справа режим с ИИ.
   Цифры досчитываются и останавливаются: «**M действий → N**», «**Y с → X с**».
2. **Цена промедления при аварии.** Красная линия-таймлайн: «0 с — сообщение → A с — авария распознана →
   B с — дежурный уведомлён». Под ней: «вручную — C с до уведомления».
3. **Сэкономлено за месяц.** Три карточки: 30 / 50 / 100 заявок в день → часы и смены в месяц.
   Формула мелко: «экономия на заявку × заявок в день × 22 рабочих дня».

Все цифры — **только из [reports/measure.md](../../reports/measure.md)**. Пока замера нет, на слайде
стоят ❓ и он не готов. Демо-цифры страницы замера (`/measure?demo=1`, «47 против 6») на слайд **не берём** —
это заглушка, а не измерение.

### 7. Архитектура и надёжность
- Одна схема: веб → API → **ядро** (пайплайн, шина событий, реестры) → **модули** (разбор, приоритет,
  исполнитель, авария, база знаний, отчёты) → **порты** (модель ИИ, речь, CMDB, история, уведомления).
- Подпись у портов: «облако сейчас → локальные модели в контуре заказчика — замена адаптера».
- Три цифры надёжности мелко: «SonarQube: 0 багов, 0 уязвимостей, 0 замечаний», «покрытие тестами 83 %»,
  «любой модуль выключается одной переменной». Источник — [reports/sonarqube-summary.md](../../reports/sonarqube-summary.md).
- ❓ Число тестов на слайд — только после свежего `pnpm check` (взять цифру из вывода).

### 8. Команда и внедрение
- Слева «1+∞: человек + агенты»: **Денис** — капитан и продукт; **Данкония** — архитектор (спецификации,
  задачи); **Семён** — кодер (код, тесты, PR). Процесс: задача → спецификация → PR → проверка.
- Справа три этапа внедрения: пилот на одной линии (4 недели) → расширение и интеграции (2–3 месяца) →
  эксплуатация в контуре заказчика. Источник — [delivery.md, раздел 4](../hackathon/delivery.md#4-план-и-описание-внедрения).
- Строка «что получит заказчик»: прототип, код, инструкция запуска, тестовый набор, отчёт о качестве и
  ограничениях, план внедрения.

### 9. Честно об ограничениях
Четыре строки, без оправданий:
- данные синтетические (история 600 заявок, CMDB, специалисты);
- одна модель ИИ в облаке; локальный контур — архитектура, не сборка;
- распознавание речи пока не подключено;
- тестовый набор маленький — цифры проверим на 30–40 реальных обращениях в пилоте.

### 10. Мост в демо
- Тёмный графитовый слайд: «Смотрим вживую». Мелко: «следующее нажатие → localhost:5173».
- Нажатие «›» → переход на `http://localhost:5173` в той же вкладке (полный экран сохраняется, если
  браузер позволяет; иначе F11 / «старт показа» в приложении — ❓ проверить на ноутбуке).
- Клавиша **V** на этом слайде открывает запасное видео демо (`media/demo.mp4`), если приложение не отвечает.

## 6. Кликер и управление

Кликер на защите — Logitech R400 (или аналог): «‹», «›», «старт показа», «чёрный экран» + лазер (аппаратный).
Он работает как клавиатура.

| Кнопка / клавиша | Действие |
|---|---|
| «›» = `PageDown`; также `→`, `↓`, `Space`, `Enter` | следующий шаг слайда или следующий слайд |
| «‹» = `PageUp`; также `←`, `↑`, `Backspace` | предыдущий шаг / слайд |
| «старт показа» = `F5` / `Shift+F5` (повторное нажатие шлёт `Esc`) | войти в полный экран; перезагрузку по F5 **перехватить** (`preventDefault`) |
| `Esc` | выйти из полного экрана (браузер делает сам) |
| «чёрный экран» = `.` или `B` | затемнить экран; повторное нажатие — вернуть |
| `F` | полный экран вкл/выкл (с клавиатуры) |
| `Home` / `End` | первый / последний слайд |
| `V` на слайде 10 | запасное видео демо |

- Шаги внутри слайда (слайды 3 и 6) тоже идут по «›», назад по «‹» — анимация откатывается без рывка.
- Номер слайда в URL (`#6`) — после перезагрузки открывается тот же слайд.
- Мышь и курсор прячутся через 2 с бездействия.
- ❓ Проверить кликер на ноутбуке владельца до защиты: какие коды реально шлёт «старт показа» и «чёрный экран».

## 7. Техника

- Папка `presentation/` в корне: `index.html`, `presentation.css`, `presentation.js`, `vendor/gsap.min.js`,
  `fonts/` (копии Manrope), `media/` (видео ручного режима и запасное видео демо).
- **Без интернета:** GSAP и шрифт лежат локально, CDN не используется (на площадке сети может не быть).
- Без сборки: открывается двойным кликом или `npx serve presentation`. ❓ Видео из `file://` в Chrome
  проигрывается, проверить на ноутбуке.
- Слайд — сцена 1920×1080, масштабируется под экран с сохранением пропорций (проектор 16:9 и 16:10).
- Анимации по [правилам анимаций](../rules/animations.md): только `opacity` и `transform`, появление ≤ 0,9 с,
  каскад ≤ 0,6 с, без бесконечных анимаций, `prefers-reduced-motion` уважается.
- Цифры слайдов 5–7 лежат в одном объекте `DATA` в начале `presentation.js` с источником у каждой —
  обновить цифры = поправить одно место.
- Папка вне `apps/`, `packages/`, `modules/` → в SonarQube не попадает и баллы кода не портит.
- PDF для платформы: ❓ формат загрузки не записан; если нужен файл — печать из браузера (`?print`,
  все шаги раскрыты, по слайду на страницу).
