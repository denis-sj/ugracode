# Сценарий демо на защите (5 минут)

Статус: draft
Дата: 2026-11-14
Связано: [../README.md](../README.md), [../hackathon/case9-brief.md](case9-brief.md#9-сценарий-защиты), [../hackathon/winning-strategy.md](winning-strategy.md), [../map/README.md](../map/README.md)

Порядок показа: **боль → разбор на глазах → проверка человеком → авария → цифры для руководителя → архитектура**.
Цель — за 5 минут показать все критерии К1–К5 и «вау» без падений.

## Подготовка (за 10 минут)

```bash
docker compose up -d --build          # db + api + web
# проверка: http://localhost:3001/api/health → {"status":"ok"}
# веб: http://localhost:5173
```

- В `.env` — ключ Polza (иначе `AI_MODE=stub`; демо-шаги работают, но без живой модели).
- `pnpm demo:reset` — база в исходное состояние (600 заявок истории, пользователи, CMDB).
- Открыть две вкладки: заявитель и диспетчер; третью — руководитель.
- Проверить, что в DevTools не видно ключей (правило secrets-and-data).

## 0:00–0:20. Вход и роли

1. Экран входа: карточки пользователей по ролям + «Войти как гость».
2. Войти **Денисом Соколовым** (заявитель, кабинет 311).

> «Один вход для четырёх ролей: заявитель, диспетчер, инженер, руководитель. Права проверяются на сервере».

## 0:20–2:00. Обращение и разбор (К1, ментор п. 1–4)

1. В чате ввести пример заказчика:
   `Корпус Б, кабинет 312, принтер HP не печатает, мигает красный индикатор`
2. Не отправлять сразу — показать подсказку и кнопки: скрепка, микрофон, телефон.
3. Отправить. Справа появляется стикер «уточняем…», в ленте — шаги разбора: «Собираем текст → Разбираем агентом → Проверяем цитаты и CMDB → Приоритет».
4. По ходу появляются поля с цитатами: корпус **Б**, кабинет **312**, оборудование **HP LaserJet Pro M404dn**, инв. `INV-000312`, IP `10.10.3.12`, приоритет **высокий** (3 из 4 полосок).
5. Агент задаёт вопрос-карточку «Сколько сотрудников затронуто?» — варианты, «Не знаю», свой ответ. Ответить **один**.
6. Стикер: статус, шкала «Собрана → Проверена → Назначена», инженер, срок.

> «Каждое поле — с цитатой и уверенностью. Агент сам сходил в CMDB и справочники; текст заявителя — данные, а не команды».

## 2:00–3:00. Диспетчер: проверка и назначение (К3, К4)

1. Переключиться на диспетчера (Анна Миронова). Очередь: сводка, фильтры **Все / Сомнительные / Готовые / Аварии**, поиск.
2. Открыть заявку: 4 шага, след «Нашёл → Сверил → Спросил → Вам», сомнительные поля жёлтым.
3. Исправить одно поле (например, кабинет 312 → 313): видно «исправил диспетчер · ИИ предлагал 312».
4. Вкладка «Исполнитель»: топ-3 с причинами («навык принтеры — 4, на смене, корпус Б, 2 открытые заявки»).
5. **Enter** — заявка назначена, окно «Назначена». В журнале — строка «ИИ предложил → человек исправил»; у инженера — уведомление.

> «ИИ предлагает, код проверяет, человек подтверждает. Счётчик действий диспетчера — замер К4».

## 3:00–3:40. Инженер замыкает цикл

1. Войти инженером (Игорь Лебедев) → «Мои задачи».
2. Открыть задачу: срок, заявитель, диагностика из базы знаний (шаги статьи), похожие решённые.
3. «Взять в работу» → записать результат «Заменил картридж, печать восстановлена» → «Выполнено».
4. Переключиться на заявителя: «Мои заявки» → «Да, всё работает» → заявка закрыта.

## 3:40–4:20. Авария (ментор п. 5)

1. Заявителем отправить: `Корпус Б, кабинет 312, принтер дымится, пахнет горелым`.
2. Открыть у диспетчера «Аварии»: **подтверждена**, красная пульсирующая точка (без красного фона), таймер, признаки с цитатами, чек-лист регламента, «почему авария», уведомлены дежурные.
3. Показать блок массовости: «Похоже на массовый сбой» — счётчик, столбики, порог; «Объявить массовым» (локальная имитация, помечено ❓).

> «Два независимых сигнала: правила и модель. При сомнении — эскалация дежурному с нужным навыком».

## 4:20–5:00. Руководитель: цифры и качество (К2, К5)

1. Дашборд: период 30 дней, 5 плиток с ▲/▼, график приоритетов, тепловая карта «день × час».
2. Горячие точки: «принтер в кабинете 312» — «Что это значит» и «Что сделать».
3. Показать `pnpm eval` → `reports/quality.md`: точность полей, выдуманные поля = 0, авария = 0 пропусков, топ-3 исполнителя, цена и время обращения.
4. Финальный слайд: архитектура (ядро + модули, агент с инструментами, порты) и «флаги фич: сырой модуль выключается одной переменной».

## Если что-то падает

- **Нет сети / модель не ответила**: переключить `AI_MODE=stub` и повторить — шаги те же, но ответы из сценариев; честно сказать «демо-режим».
- **Пустая база**: `pnpm demo:reset` (30–60 с).
- **Не открывается веб**: API живёт на 3001, веб на 5173; проверить `/api/health`.
- **Запасная копия**: второй ноутбук/сервер с тем же `.env` и `docker compose up`.

## Что не показываем

- 40 статей базы знаний и полный набор качества (только сводка).
- Выгрузку отчётов (пункты помечены «появится с О1–О8»).
- Массовый инцидент как серверную сущность (пока локальная имитация).
