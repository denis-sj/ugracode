# Сценарий демо на защите (5 минут)

Статус: draft
Дата: 2026-11-14
Связано: [../README.md](../README.md), [../hackathon/case9-brief.md](case9-brief.md#9-сценарий-защиты), [../hackathon/winning-strategy.md](winning-strategy.md), [../map/README.md](../map/README.md)

Порядок показа: **боль → разбор на глазах → звонок по QR → проверка человеком → авария → цифры для руководителя → архитектура**.
Цель — за 5 минут показать все критерии К1–К5 и «вау» без падений.

## Новый порядок защиты (с 2026-11-14)

Решение владельца: **слайды 0:00–2:35 → живое демо 2:35–5:00 до конца → вопросы**, в презентацию не
возвращаемся. Слайды, цифры и кликер — [../specs/case9-presentation.md](../specs/case9-presentation.md).
Последний слайд кликером открывает `http://localhost:5173`. На демо — **2:25**, поэтому шаги ниже
показываем сокращённо:

| Время | Шаги ниже | Что опускаем |
|---|---|---|
| 2:35–3:25 | «Обращение и разбор» | вход и роли (заявитель уже вошёл) |
| 3:25–3:55 | «Диспетчер»: правка поля, топ-3, Enter | — |
| 3:55–4:25 | «Авария» | блок массовости — только если осталось время |
| 4:25–5:00 | «Руководитель»: дашборд, горячая точка, финальная фраза | `pnpm eval` (цифры уже на слайде 5); инженер — в вопросах |

Голос в демо пока не показываем (решение владельца). Вкладки заявителя, диспетчера и руководителя
открыть заранее; слайд 10 ведёт во вкладку заявителя.

## Подготовка (за 10–15 минут)

```bash
docker compose up -d --build                 # db + api + web; первый раз 3–6 мин
curl -s http://localhost:3001/api/health     # ждать {"status":"ok"}
pnpm demo:check                              # смоук всего сценария по API, живая модель
pnpm demo:check --stub                       # то же без ключа: 1–3 с, проверки модели пропускаются
pnpm demo:check --base-url http://<сервер>:3001   # проверить запасную копию
pnpm demo:tunnel                             # HTTPS-адрес для телефона жюри и QR в терминале
```

- **`pnpm demo:tunnel`** собирает веб и запускает preview на 4173; затем поднимает Cloudflare
  или запасной Pinggy и проверяет публичные `/call` и `/api/health`. HTTPS-ссылка и QR — **в терминале**,
  во вкладке «Звонок» их нет. Телефон может использовать мобильный интернет. Для обновления ссылки:
  Ctrl+C в терминале туннеля, затем снова `pnpm demo:tunnel`. Бесплатный Pinggy живёт около 60 минут.
- **На телефоне** открыть ссылку в Safari/Chrome. На заставке бесплатного Pinggy нажать **Enter site**,
  затем «Ответить». Проверка туннеля воспроизводит этот шаг с cookie и User-Agent iPhone.
- **Перед выходом** проверить звонок на своём телефоне: разрешение микрофона, что ИИ слышен (голос RouterAI).
  На ноутбуке запасной путь — `http://localhost:5173/call` (микрофон на localhost разрешён).
  Проверка озвучки без звонка: `pnpm check:routerai` — каталог модели без ключа и живая фраза с замером задержки;
  образцы голосов пишутся в `.demo/tts/` (в git не идут). Голос меняется в `.env`: `ROUTERAI_TTS_VOICE` (по умолчанию `Kore`).

- **`pnpm demo:check`** проходит путь защиты по HTTP: вход заявителем → обращение
  «Корпус Б, кабинет 312, принтер HP не печатает, мигает красный индикатор» → разбор →
  карточка-вопрос → диспетчер подтверждает и назначает → уведомление инженеру → авария
  «идёт дым, пахнет горелым» → отчёты. Печатает чек-лист ✅/❌ и выходит с кодом 1 при провале:
  **если код 1 — на защиту не выходить**.
- Замеры прогонов 2026-11-14 (облако Polza, локальный API): весь смоук **46–55 с**, из них разбор
  обращения **17–28 с**, авария **17 с**, отчёт смены **3–5 с**; на заглушке — **0,3 с**.
- Заглушка (`--stub`) проверяет инфраструктуру и правила (поля из модуля-образца, авария по
  правилам, назначение, отчёты шаблоном); статью базы знаний и приоритет модели — только ключ.
- После смоука в базе остаются два обращения, назначение и, если прогонов было несколько,
  массовый инцидент. Перед защитой база возвращается в исходное состояние: `pnpm demo:reset`.
  `pnpm demo:reset` снова работает (проверено 2026-11-14): очищает демо-таблицы и заново сеет 600 заявок
  (№ 1…600 по времени, живые продолжаются с № 601), 14 инженеров, CMDB и 18 статей базы знаний.
  Для стенда в docker: `DATABASE_URL=postgres://ugra:ugra@localhost:5432/ugra pnpm demo:reset`.

- В `.env` — ключ Polza (иначе `AI_MODE=stub`; шаги работают, но без живой модели).
- Открыть две вкладки: заявитель и диспетчер; третью — руководитель.
- Проверить, что в DevTools не видно ключей (правило secrets-and-data).

## 0:00–0:20. Вход и роли

1. Экран входа: карточки пользователей по ролям + «Войти как гость».
2. Войти **Денисом Соколовым** (заявитель, кабинет 311).

> «Один вход для четырёх ролей: заявитель, диспетчер, инженер, руководитель. Права проверяются на сервере».

## 0:20–2:00. Обращение и разбор (К1, ментор п. 1–4)

1. В чате ввести пример заказчика:
   `Корпус Б, кабинет 312, принтер HP не печатает, мигает красный индикатор`
2. Не отправлять сразу — показать подсказку и кнопки: скрепка, микрофон, телефон.
3. Отправить. Справа появляется стикер «уточняем…», в ленте — шаги разбора: «Собираем текст → Разбираем агентом → Проверяем цитаты и CMDB → Приоритет».
4. По ходу появляются поля с цитатами: корпус **Б**, кабинет **312**, оборудование **HP LaserJet Pro M404dn**, инв. `INV-000312`, IP `10.10.3.12`, приоритет **высокий** (3 из 4 полосок).
   ⚠️ Факт трёх облачных прогонов 2026-11-14: приоритет пришёл **средний** два раза и **высокий**
   один — модель не всегда заполняет влияние и срочность. На сцене показывать фактическую полоску
   и говорить по ней («средний: работа не встала, сотрудников затронуто немного»), либо задать
   карточку «Сколько сотрудников затронуто?» и получить высокий после ответа.
5. Агент задаёт вопрос-карточку «Сколько сотрудников затронуто?» — варианты, «Не знаю», свой ответ. Ответить **один**.
6. Стикер: статус, шкала «Собрана → Проверена → Назначена», инженер, срок.

> «Каждое поле — с цитатой и уверенностью. Агент сам сходил в CMDB и справочники; текст заявителя — данные, а не команды».

## 2:00–2:50. Звонок по QR-коду (К1, К3, «вау»)

1. На экране диспетчера открыть вкладку **«Звонок»** (`/#/calls`) — **в отдельном окне браузера**, не в панели предпросмотра: жюри должно видеть его всё время. QR для подключения телефона показать из терминала заранее.
   В шапке экрана — зелёная точка «обновляется вживую» с временем последнего опроса: значит экран смотрит в тот же API. Если видно «Нужен вход диспетчером» — войти Анной Мироновой. Дать жюри телефон / попросить сканировать своим.
2. Член жюри жмёт **«Ответить»**, разрешает микрофон и говорит: «Не печатает принтер в 312-м».
3. ИИ отвечает **голосом** (синтез RouterAI, реплика сразу появляется субтитром и звучит без паузы —
   приветствие и типовые уточнения синтезированы заранее по нажатию «Ответить»), переспрашивает кабинет/корпус,
   кладёт трубку. Субтитры идут на телефоне, на проекторе в карточке звонка реплики появляются вживую (опрос 1 с),
   звучит короткий сигнал «входящий».
4. На телефоне крупно: **«Заявка № 602»** (номер звучит словами: «заявка шестьсот два»); у диспетчера — ссылка
   «Открыть заявку», разбор идёт тем же конвейером.
5. Одной строкой: «Речь распознаёт браузер телефона, на сервер уходит только текст; озвучивает модель
   `gemini-3.8-flash-lite-tts` через RouterAI, готовые фразы кэшируются; заявка собрана тем же ИИ-разбором».

> Если голос молчит (нет сети/ключа) — реплика всё равно на экране, а фразу читает `speechSynthesis` браузера:
> демо без звука не остаётся. Проверить заранее: `pnpm check:routerai` (ключ RouterAI в `.env`).

> «Ни телефонии, ни номера: QR — и человек уже говорит с диспетчерской. Заявка появляется без оператора».

## 2:50–3:30. Диспетчер: проверка и назначение (К3, К4)

1. Переключиться на диспетчера (Анна Миронова). Очередь: сводка, фильтры **Все / Сомнительные / Готовые / Аварии**, поиск.
2. Открыть заявку: 4 шага, след «Нашёл → Сверил → Спросил → Вам», сомнительные поля жёлтым.
3. Исправить одно поле (например, кабинет 312 → 313): видно «исправил диспетчер · ИИ предлагал 312».
4. Вкладка «Исполнитель»: топ-3 с причинами («навык принтеры — 4, на смене, корпус Б, 2 открытые заявки»).
5. **Enter** — заявка назначена, окно «Назначена». В журнале — строка «ИИ предложил → человек исправил»; у инженера — уведомление.

> «ИИ предлагает, код проверяет, человек подтверждает. Счётчик действий диспетчера — замер К4».

## 3:30–3:55. Инженер замыкает цикл

1. Войти инженером (Игорь Лебедев) → «Мои задачи».
2. Открыть задачу: срок, заявитель, диагностика из базы знаний (шаги статьи), похожие решённые.
3. «Взять в работу» → записать результат «Заменил картридж, печать восстановлена» → «Выполнено».
4. Переключиться на заявителя: «Мои заявки» → «Да, всё работает» → заявка закрыта.

## 3:55–4:25. Авария (ментор п. 5)

1. Заявителем отправить: `Корпус Б, кабинет 312, принтер дымится, пахнет горелым`.
2. Открыть у диспетчера «Аварии»: **подтверждена**, красная пульсирующая точка (без красного фона), таймер, признаки с цитатами, чек-лист регламента, «почему авария», уведомлены дежурные.
3. Показать блок массовости: «Похоже на массовый сбой» — счётчик, столбики, порог; «Объявить массовым» (локальная имитация, помечено ❓).

> «Два независимых сигнала: правила и модель. При сомнении — эскалация дежурному с нужным навыком».

## 4:25–5:00. Руководитель: цифры и качество (К2, К5)

1. Дашборд: период 30 дней, 5 плиток с ▲/▼, график приоритетов, тепловая карта «день × час».
2. Горячие точки: «принтер в кабинете 312» — «Что это значит» и «Что сделать».
3. Показать `pnpm eval` → `reports/quality.md`: точность полей, выдуманные поля = 0, авария = 0 пропусков, топ-3 исполнителя, цена и время обращения.
4. Финальный слайд: архитектура (ядро + модули, агент с инструментами, порты) и «флаги фич: сырой модуль выключается одной переменной».

## Если что-то падает

- **Нет сети / модель не ответила**: переключить `AI_MODE=stub` и перейти на запасную копию
  или повторить — шаги те же, но ответы из сценариев; честно сказать «демо-режим».
- **Что именно сломалось**: `pnpm demo:check --stub` (0,3 с) показывает, жив ли API, есть ли
  модули, пользователи, очередь, авария и отчёты; `pnpm demo:check` — то же с живой моделью.
- **Пустая база**: `pnpm demo:reset` (30–60 с; ❗ сейчас падает на `ai_cache` — обходной путь
  `docker compose down -v && docker compose up -d --build`).
- **Не открывается веб**: API живёт на 3001, веб на 5173; проверить `/api/health`.
- **Pinggy не грузится на телефоне**: `pnpm demo:tunnel --serveo`, новая ссылка в терминале;
  на заставке нажать **Continue to Site**. Этот режим использует preview 4174 и тот же API.
- **Туннель/телефон подвёл**: QR не появился в терминале — `pnpm demo:tunnel` не запущен или нет `cloudflared`
  (`brew install cloudflared`); туннель режет Wi-Fi — раздать интернет с телефона владельца. Совсем без телефона —
  звонок на ноутбуке `http://localhost:5173/call` или `pnpm voice:sim`: те же три звонка, реплики и номера заявок.
  **Если сеть блокирует UDP-DNS** (cloudflared получает адрес, но отдаёт 530 и в логе `DNS prerequisite failed`) —
  запасной туннель по SSH: `ssh -p 443 -R0:localhost:5173 a.pinggy.io`; адрес `https://….pinggy-free.link` уже разрешён
  в Vite. На телефоне будет предупреждение pinggy — «Enter site». Живёт 60 минут, для защиты лучше выключить VPN.
- **Телефон не слышит / не говорит**: разрешение микрофона отклонено — появится поле ввода текста, ИИ ответит голосом;
  Firefox распознавать речь не умеет (Chrome/Safari умеют). Синтез молчит на iOS, если разговор начат не кнопкой «Ответить».
- **ИИ говорит не голосом RouterAI**: нет `ROUTERAI_API_KEY`/сети или ответ дольше 3 с — фраза читается
  `speechSynthesis` браузера, текст всегда на экране. Проверить ключ и модель: `pnpm check:routerai`;
  на защите достаточно сказать «запасной голос браузера, реплики те же».
- **Запасная копия**: второй ноутбук/сервер с тем же `.env` и `docker compose up`; адрес ❓ у
  владельца, проверять `pnpm demo:check --base-url http://<сервер>:3001`.

## Что не показываем

- 40 статей базы знаний и полный набор качества (только сводка).
- Выгрузку отчётов (пункты помечены «появится с О1–О8»).
- Массовый инцидент как серверную сущность (пока локальная имитация).


### Светлый интерфейс — первый этап референсов, 2026-11-14

На старте обращения можно выбрать пример: он подставится в поле без отправки.
Отправить стрелкой или Enter; продолжить уточнения и проверить стикер заявки.
Профиль открывается по аватару в общем доке; показывает место и технику из API,
смена пользователя — в главной карточке. История заявителя — «Мои заявки».
Композиции остальных ролей пока требуют переноса; браузерная приёмка ожидается.
