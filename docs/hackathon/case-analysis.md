## Требования владельца к кейсу

1. **Не лёгкий**: технически сильный, жюри должно увидеть сложность.
2. **Очень красивый визуально**: анимации, «вау» на защите.
3. **Есть будущее**: можно развивать после хакатона.
4. Ограничение: команда из одного человека, ~24 часа.

## Рекомендация: кейс 9 «Диспетчерская с ИИ»

**Сложность.** Цепочка ИИ-задач: классификация обращения, извлечение данных (объект, кабинет,
серийный номер, симптомы), подбор исполнителя с учётом навыков и загрузки, поиск решения
(база знаний и похожие заявки через эмбеддинги), распознавание речи, тональность, прогноз
нагрузки и риска SLA. Плюс инженерия: порог уверенности, проверка человеком, журнал действий, роли.

**Визуал.**
- Разбор обращения в реальном времени: фрагменты текста подсвечиваются и «перелетают» в поля заявки, шкала уверенности заполняется.
- Живой поток карточек по этапам: принято → разобрано → назначено → решено.
- Режим аварии: интерфейс уходит в красный тревожный режим.
- Карта или схема объектов с точками проблем.
- Графики пиков нагрузки и прогноз риска SLA.
- Экран «с ИИ против без ИИ»: таймер и счётчик кликов. Этого сравнения прямо требуют критерии.

**Будущее.** Диспетчерская с ИИ нужна любой сервисной службе: ИТ-поддержке, ЖКХ, заводам,
сервисным центрам. Заказчик крупный, есть шанс на пилот.

## Реализуемость кейса 9 за 24 часа

Оценка от 2026-11-14 (сессия [../sessions/2026-11-14-case9-feasibility.md](../sessions/2026-11-14-case9-feasibility.md)).

**Вывод:** реализуемо только с жёстко урезанным объёмом. Делаем то, что заказчик назвал
обязательным: «Текст → поля и теги → приоритет → рекомендация исполнителя → решение из базы
знаний → проверка человеком» + отчётность, плюс один «вау-момент».

Часы работы одного исполнителя (при параллельных агентах время на часах меньше, см. ниже):

| Блок | Часы | Статус |
|---|---|---|
| Каркас, синтетические данные (история заявок, база знаний, инженеры, объекты) | 2 | обязательно |
| ИИ-разбор: категория, приоритет, поля, уверенность (структурированный ответ модели) | 3 | обязательно |
| Подбор исполнителя (навыки + загрузка) | 1,5 | обязательно |
| Поиск решения в базе знаний и похожих заявок | 2 | обязательно |
| Экран диспетчера: правка, подтверждение, журнал действий, роли | 3,5 | обязательно |
| Отчётность: графики | 1,5 | обязательно |
| 5–10 тестовых обращений + скрипт точности → отчёт о качестве | 1,5 | обязательно (критерий) |
| Экран «с ИИ / без ИИ»: таймер и счётчик ручных действий | 1,5 | обязательно (критерий) |
| **Ядро итого** | **~16,5** | |
| Дизайн-система + анимации «вау» (поля заполняются на глазах, красный режим аварии) | 3 | важно для победы |
| Презентация | 2 | обязательно |
| Деплой, видеозапись демо, 2–3 прогона защиты | 2 | обязательно |
| **Всего** | **~23,5** | |

Сокращения (предложение, ❓ ждёт «ок» владельца):

1. Одно приложение (Next.js: и интерфейс, и сервер) + PostgreSQL вместо Next.js + FastAPI — экономит 1,5–2 часа на стыковке.
2. Роли — переключатель из трёх готовых пользователей (диспетчер, инженер, руководитель), без настоящей авторизации.
3. Речь — один заранее записанный синтетический звонок → текст → черновик заявки; только если ядро готово к 16-му часу (~1 час).
4. Не делаем: настоящий чат-бот, тональность, прогноз нагрузки. Они идут на слайд «план развития».

С параллельными агентами (режим владельца) ядро делится на 3–4 независимых потока, и время на часах
сокращается примерно вдвое. Узкое место — ревью и сборка у владельца, см.
[winning-strategy.md](winning-strategy.md#работа-параллельными-агентами).

Главный риск — стабильность демо: кэш ответов модели для демо-обращений и видеозапись как запасной вариант.

## Финалисты владельца: кейс 8 против кейса 2 (2026-11-14)

Владелец прислал презентации двух кейсов как «двух претендентов». Сравнение по критериям
([criteria.md](criteria.md)) и требованиям владельца:

| Что оцениваем | 8. Новостной радар | 2. Фабрика новостей |
|---|---|---|
| Ясность задачи («Соответствие теме», 4) | Три чётких пункта + бонус, легко закрыть все | Статусная модель и 8 ролей; «как показать» — просто «Демонстрация» |
| Технологичность (3) | Сильная: сбор по расписанию, ИИ-отбор по географии и теме, склейка дублей через эмбеддинги, оценка важности, выжимки | Слабее: по сути учётная система; ИИ в задаче нет, можно только добавить сверху |
| Вау-визуал | Буквальный радар над картой Югры, находки «вспыхивают» на карте, живая лента | Канбан сюжетов и таймлайн эфира — аккуратно, но привычно |
| Сценка | Живая: публикуем новость в Telegram-канале со сцены → через секунды радар её ловит, телефон редактора звенит | Забавная: «я один — вся редакция», переключаюсь между 8 ролями |
| Гора классных фич | Да, много «умных» фич (см. [../ideas/case8-features.md](../ideas/case8-features.md)) | Фичи в основном учётные: роли, статусы, задания, хронометраж |
| Объём для одного человека | Компактное ядро, остаётся время на полировку; сборщики источников легко делить между агентами | Широкий: 8 ролей × свои экраны, риск сделать всё тонко |
| Будущее | Продукт для любой редакции, пресс-службы, PR-агентства, администрации | Внутренняя система одного телеканала |
| Риски | Источники могут блокировать сбор или менять вёрстку; VK требует ключ API. Защита: RSS + публичные веб-страницы Telegram-каналов + кэш + свой тестовый канал для демо | Обязательны Docker и PostgreSQL, 152-ФЗ, аудит — больше «обязательной рутины» |

**Рекомендация Данконии: кейс 8 «Новостной радар».** Он лучше подходит под критерии экспертов
(тема, технологичность, демонстрация) и под пожелания владельца (вау, много умных фич, живая сценка).
Кейс 2 сильнее только там, где важны роли и процессы, но это скорее учётная система, чем «вау».

Уточнение по кейсу 2 (тот же день): разбор требований, 23 фичи, расчёт часов и демо — в
[../ideas/case2-features.md](../ideas/case2-features.md). Итог: ~31,5 часа работы одного исполнителя,
с 3–4 параллельными агентами успеваем; кейс хорошо делится на независимые потоки. У кейса 2 есть
явные критерии (5 пунктов), что упрощает «Соответствие теме». «Вау» и «Технологичность» нужно
добавлять самим: реальное время, режим «Аппаратная», суфлёр по голосу, ИИ-расшифровка.
