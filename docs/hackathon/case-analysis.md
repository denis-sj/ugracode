## Требования владельца к кейсу

1. **Не лёгкий**: технически сильный, жюри должно увидеть сложность.
2. **Очень красивый визуально**: анимации, «вау» на защите.
3. **Есть будущее**: можно развивать после хакатона.
4. Ограничение: команда из одного человека, ~24 часа.

## Рекомендация: кейс 9 «Диспетчерская с ИИ»

**Сложность.** Цепочка ИИ-задач: классификация обращения, извлечение данных (объект, кабинет,
серийный номер, симптомы), подбор исполнителя с учётом навыков и загрузки, поиск решения
(база знаний и похожие заявки через эмбеддинги), распознавание речи, тональность, прогноз
нагрузки и риска SLA. Плюс инженерия: порог уверенности, проверка человеком, журнал действий, роли.

**Визуал.**
- Разбор обращения в реальном времени: фрагменты текста подсвечиваются и «перелетают» в поля заявки, шкала уверенности заполняется.
- Живой поток карточек по этапам: принято → разобрано → назначено → решено.
- Режим аварии: интерфейс уходит в красный тревожный режим.
- Карта или схема объектов с точками проблем.
- Графики пиков нагрузки и прогноз риска SLA.
- Экран «с ИИ против без ИИ»: таймер и счётчик кликов. Этого сравнения прямо требуют критерии.

**Будущее.** Диспетчерская с ИИ нужна любой сервисной службе: ИТ-поддержке, ЖКХ, заводам,
сервисным центрам. Заказчик крупный, есть шанс на пилот.
