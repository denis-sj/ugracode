## Критерии по кейсам (с платформы, дословно по смыслу)

### Кейс 9. Диспетчерская с ИИ (Газпром трансгаз Сургут) — рекомендуемый

1. Подготовить 5–10 тестовых обращений.
2. Проверить, правильно ли ИИ заполняет поля и определяет исполнителя.
3. Показать, как диспетчер исправляет (при необходимости) и подтверждает заявку.
4. Сравнить количество ручных действий с ИИ и без него на одном примере.
5. Стабильность решения и архитектурная логика.

Что показать на защите (из «ожидаемого результата»): типовое обращение, аварийный случай и заявку
с нехваткой данных. Сравнить время обработки с ручным сценарием.
Что передать заказчику: прототип, код, инструкцию запуска, тестовый набор, отчёт о качестве
и ограничениях, план и описание внедрения.

### Кейс 4. Учёт ПО, SAM (Сургутнефтегаз)

1. Базовый MVP (60% успеха): работающий бэкенд, точный расчёт лицензий, чистый интерфейс.
2. Фактор применения ИИ (бонусные баллы): работающая интеграция с ИИ.
3. Стабильность решения и архитектурная логика.

### Кейс 2. Фабрика новостей (СургутИнформТВ)

1. Соответствие функциональным требованиям (статусная модель, роли).
2. Стек Docker + PostgreSQL.
3. Проработка интеграций и безопасности (152-ФЗ, аудит).
4. Качество UX/UI и удобство карточки новости.
5. Работоспособность демо.

### Кейс 3. А.Г.Е.Н.Т (СургутИнформТВ)

1. Работоспособность MVP и единого центрального ядра.
2. Качество парсера и интеграции с нейросетями (реферирование, рерайт, заголовки).
3. Локальный запуск нейросетей.
4. Стек Docker + PostgreSQL.
5. Удобство интерфейса для редактора и контент-менеджера.
