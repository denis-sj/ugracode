## 039. Голос ИИ-оператора: озвучка RouterAI — 2026-11-14
Кто: Семён · PR: — (ветка `feature/voice-tts`) · Заменяет браузерный синтез из 036
Итог: реплики ИИ-оператора озвучивает модель `google/gemini-3.8-flash-lite-tts` через RouterAI (единственное
исключение из правила «только Polza», решение владельца) — порт `TtsPort` в `packages/core`, адаптер
`packages/adapters/src/tts/` (`RouterAiTts`, `StubTts`, идемпотентный `pcmToWav`), маршрут ядра `POST /api/tts`
(право `appeal.create`, текст ≤ 400 символов, кэш `sha256(голос+текст)` на 200 фраз, 503 без ключа).
Страница `/call`: реплика сразу субтитром, звук по готовности, `unlock()` и предсинтез приветствия/типовых
уточнений по жесту «Ответить» (после гостевого входа), запасной `speechSynthesis` при сбое или ответе дольше
3 с. Номер заявки в прощании называется словами («заявка шестьсот два»), число в текст превращает сервер
(`modules/voice-call/server/format.ts`). Ключ не уходит ни в ответы, ни в логи (санитизация ошибок).
Проверка API: `pnpm check:routerai` — каталог модели без ключа + живой синтез 4 голосами: **1,7–2,5 с**
на фразу 4–5 с, значит цель ≤ 2 с держится кэшем и предсинтезом, а не скоростью провайдера. RouterAI
отдаёт готовый WAV даже при `response_format: 'pcm'` — обёртка не должна дублировать заголовок. Замеры
и выбор голоса (`Kore`, меняется `ROUTERAI_TTS_VOICE`) — в `docs/knowledge/environments.md`.
Тесты: адаптер и обёртка WAV, маршрут (кэш, лимит, 401/403/400/503, ключ не утекает), номер словами,
клиент озвучки и запасной путь — зелёные по затронутым пакетам. ❓ В браузере на ноутбуке и по QR с телефона
не прогонялось после слияния: проверять `http://localhost:5173/call` с ключом и без (`ROUTERAI_API_KEY=`
→ должен говорить голос браузера).
