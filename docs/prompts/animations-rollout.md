# Промпт: внедрить анимации на все экраны

Статус: active
Дата: 2026-11-14
Связано: [../../AGENTS.md](../../AGENTS.md), [../rules/animations.md](../rules/animations.md), [frontend-kickoff.md](frontend-kickoff.md), [../specs/case9-ui-design.md](../specs/case9-ui-design.md)

Назначение: дать агенту-кодеру задачу пройти все экраны и довести анимации до правил.
Как использовать: открыть новую сессию в папке репозитория и вставить блок ниже.

```text
Ты Семён — кодер проекта (роль в AGENTS.md). Зона — ФРОНТЕНД, задача — анимации на всех экранах.

ПРОЧИТАЙ СНАЧАЛА (в этом порядке)
1. AGENTS.md — роли, критерии готовности.
2. docs/rules/animations.md — ★ ГЛАВНОЕ: как делать анимации, чем, что запрещено. Это закон для задачи.
3. packages/ui/src/motion.ts — весь код анимаций (GSAP, AutoAnimate, Motion, canvas-confetti).
4. docs/specs/case9-ui-design.md, раздел 2.3 и раздел 4 — что анимируется на каждом экране.
5. docs/map/features/ui-shell.md и modules/registry.web.ts — какие экраны есть и где их код.
Образец готового экрана: modules/dispatcher-review/web/QueuePage.tsx.

ЧТО УЖЕ ЕСТЬ (не переделывай)
- useBlockMotion подключён в apps/web/src/App.tsx на весь контент: блоки любой страницы появляются
  каскадом, догруженные блоки въезжают сами, есть страховка от «залипшей» прозрачности.
- Card, StatTile, Sticker, StepBlock, ConfidenceBar, ProgressScale, Modal анимируются сами.

ЧТО СДЕЛАТЬ — пройти КАЖДЫЙ экран всех ролей (заявитель, диспетчер, инженер, руководитель, вход, профиль)
1. Открыть экран в браузере, переключиться на другую вкладку и обратно. Записать, что видно:
   - какие блоки въезжают целиком одним куском, хотя должны по отдельности → пометить `data-reveal`;
   - что дёргается или мигает (двойная анимация: CSS `animation`/`.ugra-rise` + GSAP) → оставить одну;
   - что анимируется зря (фон, сетка, шапка таблицы, декор) → `data-motion="off"` или `aria-hidden`;
   - какие свои «стеклянные» div можно заменить на Card.
2. Списки, где строки добавляются/удаляются/переставляются (уведомления, история обращений,
   задачи инженера, аварии, журнал, исполнители, мои заявки, база знаний) → useListMotion на родителя строк.
3. Ключевые моменты сценария защиты (docs/hackathon/case9-brief.md, раздел 9):
   - «Заявка назначена» — Modal tone="ok" (пружина + конфетти);
   - «Объявить массовым инцидентом» — заметный, но без конфетти (авария — не праздник);
   - чат: сообщения и карточки-вопросы въезжают по одному, стикер заявки заполняется полями;
   - «Качество ИИ» и «С ИИ / без ИИ» — ячейки и цифры появляются по очереди (revealBlocks/countUp).
4. Новая анимация, которой нет в motion.ts, → добавить функцию туда (с prefersReducedMotion),
   тест — в packages/ui/tests/motion.test.ts. В модулях gsap/motion/auto-animate/confetti НЕ импортировать.

КАК ПРОВЕРИТЬ
- Стенд: Docker (Postgres) + `pnpm dev:api` + `pnpm dev:web`; войти по очереди каждой ролью.
- Каждый экран: блоки въезжают, ничего не остаётся полупрозрачным, нет рывков; появление ≤ 0,9 с.
- Включить «Уменьшить движение» в системе — анимаций нет, всё видно сразу.
- `pnpm check` и `python3 -m unittest discover -s tests` — зелёные.

ПРАВИЛА
- Работать в ветке, не в main. Ничего не коммитить без просьбы владельца.
- Правки в чужих модулях — минимальные (атрибут, ref, хук), без переделки логики.
- В конце: обновить docs/map/features/ui-shell.md (что анимировано где) и, если появилось новое
  правило, — docs/rules/animations.md. Владельцу — короткий список: экран → что сделано → что не удалось.

ПЕРВЫЙ ШАГ
Прочитай файлы выше, пройди экраны в браузере и напиши владельцу план: экран → что поменять.
Только после «ок» — код.
```
