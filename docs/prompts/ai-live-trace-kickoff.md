«мыслей» модели.

ГДЕ В КОДЕ
- Чат: modules/clarify-chat/web/ChatPage.tsx (строка busy «Разбираю обращение»), useRunStream.ts, format.ts.
- Сервер: apps/api/src/server.ts (POST /api/appeals, GET /api/appeals/:id/stream), packages/core/src/agent.ts (AgentStep, событие agent.step),
  packages/core/src/pipeline.ts, packages/contracts/src/api.ts (RunStreamEvent).
- Сейчас POST /api/appeals выполняет разбор синхронно, а чат лишь проигрывает готовую историю с паузой. Для живого журнала нужен фоновый режим (см. задачу 035, п. 2).

ПРАВИЛА
- Работай в ветке feature/ai-live-trace, не в main. Ничего не коммить без просьбы владельца. Чужие незакоммиченные изменения не откатывай, чужие файлы не трогай.
- Правка общего контракта RunStreamEvent — отдельным маленьким коммитом после просьбы владельца; без параметра async старое поведение POST /appeals не меняется.
- Заявителю нельзя показывать сырые args, JSON, служебные подсказки, ID и персональные данные других людей. Только человеческие подписи и короткие итоги.
- Шрифт в журнале не мельче 14 px, никаких длинных пояснительных абзацев. Светлая и тёмная темы — только через токены. Без градиентных кнопок и свечения.
- Тесты: сервер (фоновый режим, порядок событий, нет утечек данных, ветки ошибки), клиент (редьюсер, раскрытие/сворачивание). `pnpm check` зелёный,
  SonarQube без новых Blocker / Critical / Major.
- Проверь в браузере (.claude/launch.json: api и web): строка раскрывается, шаги идут по ходу, после разбора остаётся «Разобрал за N с · ход работы», обе темы.

3. В конце: запись в docs/history/2026-11.md, карта фичи, удали файл задачи 035 в том же PR, верни владельцу короткий отчёт со скриншотом раскрытого журнала.
