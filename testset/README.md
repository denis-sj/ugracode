# Тестовый набор: 10 обращений

Эталон для критерия К2: `testset/cases/NN-*.json` — обращение и ожидаемые поля, приоритет, авария, топ-3
исполнителей, статья базы знаний. `testset/stubs/NN.json` — ответ заглушки модели в формате `AiExtraction`
для `AI_MODE=stub`, цитаты берутся дословно из текста обращения.

Состав: пример заказчика (принтер HP, корпус Б, каб. 312), почта, 1С с IP и кодом ошибки,
две аварии (сеть в корпусе В, дым на промплощадке), два неполных обращения (06 — совсем пустое,
07 — только мышь без места), спокойное критичное, сленг с опечатками, расшифровка звонка
(`channel: phone`, `audioFile`) и скриншот ошибки 1С (`channel: screenshot`, `imageFile`).

Запуск: `pnpm eval` (появится в задаче 012/качество) — гоняет тот же пайплайн по набору и пишет
`reports/quality.md`. Для отладки без модели: `AI_MODE=stub`, ответы берутся из `testset/stubs/`.

Правило: **на контрольном наборе не настраиваем.** Тексты, эталон и заглушки меняем только при явной
ошибке в них; подгонять промпты под эти 10 обращений нельзя. Настроечный набор — отдельно в `testset/dev/`
(задача 012), другие тексты с теми же полями.

Эталон `expected.fields` использует ключи из `data/fields.json`; `priority` — из `PriorityLevel`
(5 уровней, `emergency` выставляет модуль аварии). Пустое обращение 06 получает средний приоритет до
уточнения диспетчером — это ожидаемое поведение, а не ошибка разбора.
