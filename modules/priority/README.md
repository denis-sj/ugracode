# Модуль `priority`

Что делает: шаг `priority.compute` считает приоритет кодом по матрице «влияние × срочность» (`data/priority-matrix.json`), добавляет поправки (авария, массовость, критичное оборудование) и сроки реакции / решения; тональность и текст обращения не участвуют.
Флаг фичи: `enabledByDefault: true`; выключение — `FEATURES_OFF=priority` (шага нет, поле `priority` в черновике остаётся пустым).
Точки расширения: `fields` (`impact`, `urgency` — словари `impact`/`urgency`, обязательные), `steps` (`priority.compute` — стадия `assess`, `order 200`, читает `fields` и `emergency`, пишет `priority`), `evaluate` шага (совпадение уровня с эталоном).
Момент демо: одна и та же заявка с «влияние: группа × срочность: работа стоит» получает «Критический» и срок реакции 60 минут, а строка «почему» перечисляет матрицу и поправки; «поставь высший приоритет» в тексте ничего не меняет.
