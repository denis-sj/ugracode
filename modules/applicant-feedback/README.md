# Модуль `applicant-feedback`

Что делает: шаг `applicant-feedback.draft` (стадия `respond`, `order 100`) собирает кодом сообщение заявителю «Заявка № … принята, приоритет …, срок решения — …» из полей, приоритета и сроков; модель `cheap` в облачном режиме может только переписать формулировку, числа обязаны совпасть с шаблоном, иначе остаётся шаблон.
Подписчик `ticket.confirmed` отправляет заявителю «Заявка принята, исполнитель …»: сообщение `text` в `appeal_message` (`deps.db.saveAppealMessage`), уведомление в колокольчик и через `NotificationPort`; ошибки каналов назначение не валят.
Точки расширения: `steps` (`applicant-feedback.draft`, `reads: fields, priority`, `writes: replyDraft`), `subscribers` (`ticket.confirmed`), маршрут `POST /api/m/applicant-feedback/tickets/:id/reply` (право `tickets.edit`) — исходящий ответ диспетчера в чат.
Флаг фичи: `enabledByDefault: true`; выключение — `FEATURES_OFF=applicant-feedback` (черновика нет, ответ пишет диспетчер; подтверждение заявки работает как раньше).
Момент демо: после подтверждения заявки заявитель сразу получает сообщение с исполнителем и сроком, а диспетчер в слоте `ticket.footer` видит готовый черновик, может поправить, скопировать или отправить его.
