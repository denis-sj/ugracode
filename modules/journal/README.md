# Модуль `journal`

Что делает: веб-экран `/journal` «Журнал действий» диспетчера (дизайн, экран 11) читает `GET /api/events?limit=300`, подписывает авторов из `GET /api/users`, номера заявок — из `GET /api/tickets?limit=200` и показывает правки «ИИ предложил → человек исправил».
Фильтры: Все / Правки ИИ / Подтверждения / Аварии, поиск и период «Сегодня / 7 дней»; строки — время, автор, событие, «было → стало» с подсветкой отличий и ссылка `#/review?id=…`.
Сводка справа: топ-5 полей по `ticket.field.corrected` — подсказка, что чаще исправляют в настройке модели; пустое состояние честное, без выдуманных цифр.
Точки расширения: только веб (`defineWebModule`, страница `/journal`, роли `dispatcher`/`admin`/`manager`); серверных шагов и событий у модуля нет — это читатель общего журнала ядра.
Момент демо: диспетчер исправляет поле в проверке заявки, открывает «Журнал» — правка сверху с парой «было → стало», а в топе растёт доля этого поля.
