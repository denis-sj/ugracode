# Модуль `voice-call`

Что делает: живой ИИ-оператор в браузере телефона. Жюри сканирует QR на экране диспетчера → открывается `/call` → «Ответить» → разговор голосом: браузер распознаёт речь (`SpeechRecognition`, `ru-RU`), на сервер уходит только текст, `POST /api/m/voice-call/turn` отвечает короткой фразой (`ports.llm.chat`, промпт `prompts/dialog.v1.md`), браузер её озвучивает (`speechSynthesis`). После `done` или «Завершить» — `POST /api/m/voice-call/end`: итог звонка идёт в `deps.appeals.submit(channel: 'phone', {wait: false})`, то есть тем же разбором, что чат, а разговор пишется в чат обращения.
Точки расширения: маршруты `/turn`, `/end`, `/calls`, `/calls/active`, `/calls/:id`, `/public-url` (права `appeal.create` у звонка, `tickets.queue` у чтения); чистое ядро `server/dialog.ts` (`hasEmergencySign`, `speakable`, `parseReply`) и `server/service.ts`; состояние звонков `server/calls.ts` в памяти процесса с TTL 30 мин; экраны `web/CallsPage.tsx` (диспетчер) и `web/PhoneCallPage.tsx` (публичная `/call`); лимиты `RateLimiter` — 6 звонков и 30 реплик в минуту с адреса; `ModuleDeps.appeals` и `headers` в ctx — правка ядра по варианту A.
Флаг фичи: `enabledByDefault: true`; выключение — `FEATURES_OFF=voice-call` (маршруты `/api/m/voice-call/*` отвечают 404, страница `/call` не работает, остальное живёт).
Момент демо: жюри сканирует QR с проектора, говорит «не печатает принтер в 312-м», ИИ переспрашивает голосом, кладёт трубку — на экране диспетчера звонок с репликами и заявка `З-…` в очереди.
Ограничение: распознаёт и озвучивает **браузер** (Google в Chrome, Apple в Safari), звук на сервер не идёт; без `SpeechRecognition` (Firefox, часть Android) или без доступа к микрофону — запасной ввод текстом; состояние звонков в памяти процесса — после перезапуска API экран звонков пуст, заявки остаются.

## Как позвонить с телефона

Микрофон в браузере работает только на `https://` (исключение — `localhost` на ноутбуке).

```bash
pnpm dev:api            # API на 3001
pnpm dev:web            # Vite на 5173
pnpm demo:tunnel        # в отдельном терминале: cloudflared → https://<случайно>.trycloudflare.com
```

1. Нужен `cloudflared` один раз: `brew install cloudflared`. Туннель запускается без аккаунта.
2. `pnpm demo:tunnel` печатает адрес и QR страницы `/call` и пишет адрес в `.demo/public-url` (файл в `.gitignore`).
   Туннелируется только Vite (5173): он сам проксирует `/api` на API.
3. Откройте экран диспетчера `http://localhost:5173/#/calls` — QR и адрес подтянутся из `GET /api/m/voice-call/public-url`
   в течение 15 с. Покажите QR на проекторе.
4. На телефоне: сканировать QR → «Ответить» → разрешить микрофон → говорить. Если браузер не умеет распознавать
   речь или микрофон запрещён — появится поле ввода текста, ИИ всё равно ответит голосом.
5. `PUBLIC_WEB_URL` в `.env` важнее туннеля: если задан постоянный HTTPS-адрес (сервер владельца), QR ведёт на него.

Без телефона весь путь проверяется скриптом: `pnpm voice:sim` (сценарии в `testset/calls/*.json`, код выхода ≠ 0, если заявка не создана).
