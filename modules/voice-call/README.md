# Модуль `voice-call`

Что делает: живой ИИ-оператор в браузере телефона. Жюри сканирует QR в терминале → открывается `/call` → «Ответить» → разговор голосом: браузер распознаёт речь (`SpeechRecognition`, `ru-RU`), на сервер уходит только текст, `POST /api/m/voice-call/turn` отвечает короткой фразой (`ports.llm.chat`, промпт `prompts/dialog.v1.md`), браузер её озвучивает (`speechSynthesis`). После `done` или «Завершить» — `POST /api/m/voice-call/end`: итог звонка идёт в `deps.appeals.submit(channel: 'phone', {wait: false})`, то есть тем же разбором, что чат, а разговор пишется в чат обращения.
Точки расширения: маршруты `/turn`, `/end`, `/calls`, `/calls/active`, `/calls/:id`, `/public-url` (права `appeal.create` у звонка, `tickets.queue` у чтения); чистое ядро `server/dialog.ts` (`hasEmergencySign`, `speakable`, `parseReply`) и `server/service.ts`; состояние звонков `server/calls.ts` в памяти процесса с TTL 30 мин; экраны `web/CallsPage.tsx` (диспетчер) и `web/PhoneCallPage.tsx` (публичная `/call`); лимиты `RateLimiter` — 6 звонков и 30 реплик в минуту с адреса; `ModuleDeps.appeals` и `headers` в ctx — правка ядра по варианту A.
Флаг фичи: `enabledByDefault: true`; выключение — `FEATURES_OFF=voice-call` (маршруты `/api/m/voice-call/*` отвечают 404, страница `/call` не работает, остальное живёт).
Момент демо: жюри сканирует QR с проектора, говорит «не печатает принтер в 312-м», ИИ переспрашивает голосом, кладёт трубку — на экране диспетчера звонок с репликами и заявка `З-…` в очереди.
Ограничение: распознаёт и озвучивает **браузер** (Google в Chrome, Apple в Safari), звук на сервер не идёт; без `SpeechRecognition` (Firefox, часть Android) или без доступа к микрофону — запасной ввод текстом; состояние звонков в памяти процесса — после перезапуска API экран звонков пуст, заявки остаются.

## Как позвонить с телефона

Микрофон в браузере работает только на `https://` (исключение — `localhost` на ноутбуке).

```bash
pnpm demo:tunnel
```

API должен быть запущен (`pnpm dev:api` или `docker compose up`). Команда собирает веб,
запускает preview на 4173 (либо использует уже работающий) и выдаёт временную HTTPS-ссылку `/call`
и QR **в терминале**. Вкладка «Звонок» показывает только разговоры и заявки, без QR и ссылки.

1. Основной туннель — `cloudflared` (`brew install cloudflared` один раз), запасной — Pinggy через SSH.
2. Перед выдачей ссылки проверяются публичная `/call` и `/api/health`: адрес из лога ещё не означает доступность.
   Cloudflare не отвечает — команда пробует Pinggy. Заставка Pinggy не считается работающей страницей.
3. Открыть ссылку на телефоне → «Ответить» → разрешить микрофон. В Chrome/Safari доступно распознавание речи;
   если оно недоступно, остаётся текстовый ввод. Телефон может использовать мобильный интернет.
   Бесплатный Pinggy сначала показывает собственную страницу: нажать **Enter site**. Открывать в Safari/Chrome.
   API и озвучка отправляют `X-Pinggy-No-Screen`, чтобы заставка не подменяла ответы во время разговора.
4. На ноутбуке открыть `http://localhost:5173/#/calls` под диспетчером: разговор подтягивается раз в секунду из API.
5. Для нового адреса: Ctrl+C в терминале туннеля, затем снова `pnpm demo:tunnel`. Старый адрес больше не использовать.
   Pinggy бесплатного тарифа живёт около 60 минут; терминал туннеля должен оставаться открытым.
6. `pnpm demo:tunnel --dev` использует запущенный dev-сервер 5173; `DEMO_TUNNEL_TARGET` задаёт свой HTTP-сервер.
   `.demo/public-url` хранит последний проверенный адрес. `PUBLIC_WEB_URL` важнее файла только в API адреса,
   но ссылка в терминале всегда соответствует новому туннелю.

Без телефона весь путь проверяется скриптом: `pnpm voice:sim` (сценарии в `testset/calls/*.json`, код выхода ≠ 0, если заявка не создана).

Если после Enter site страница долго загружается, видны текст подключения и кнопка «Обновить».
Экран звонка загружается отдельно от остальных экранов диспетчерской. При ошибке сети вместо
белого экрана выводится подсказка; повторить загрузку можно кнопкой «Обновить».

## Запасной домен, если Pinggy не открывается на телефоне

`pnpm demo:tunnel --serveo` — собирает веб, запускает отдельный preview на 4174 и выдаёт
адрес Serveo. На первом открытии в браузере нажать **Continue to Site**; далее — «Ответить».
Cloudflare и Pinggy в этом режиме не запускаются. Телефон и диспетчер используют тот же API.
